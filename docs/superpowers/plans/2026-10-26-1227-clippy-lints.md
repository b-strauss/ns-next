# Four Clippy Lints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cargo clippy --workspace --all-targets` is warning-free with four more lints enabled workspace-wide: `undocumented_unsafe_blocks`, `allow_attributes_without_reason`, `cast_possible_truncation` and `cast_sign_loss`. Every narrowing cast is audited, and a cast that nothing bounds is fixed as a defect.

**Architecture:** The first two lints go in at once. They have 28 sites and no unsafe hit.

The two cast lints have 331 unique sites today: 290 outside tests, about 40 in tests. They are worked area by area against command-line flags (`-W clippy::cast_possible_truncation -W clippy::cast_sign_loss`). `Cargo.toml` enables them only in the last task, so every commit before it passes the `commit` gate as it stands.

Each site takes one of the five forms under "The forms a cast takes". Test code allows the two cast lints instead of rewriting its casts.

**Tech Stack:** Rust 1.98.0, edition 2021. `cast_unsigned()`/`cast_signed()` are stable. No new dependency.

**Spec:** `docs/OPEN-WORK.md`, "Code quality follow-ups", the first item. It was decided with the user on 2026-10-26. This plan carries its decisions, and the item is removed in Task 7.

## Global Constraints

- **Invariants:** every invariant in `CLAUDE.md` holds. Especially:
  - an image is untrusted input: no byte sequence may panic;
  - `vm.rs` holds no dispatch logic;
  - names are written out (`min_ident_chars`).
- **No behaviour change.** No golden, no `run-corpus` output and no benchmark outcome changes, with one exception: a cast found unbounded is a defect, and its fix may change an outcome. That fix needs a test that failed before it, and it goes into its own `fix:` commit.
- **Allowed and expected attributes:**
  - Every `#[allow]` becomes `#[expect(<lint>, reason = "…")]`.
  - It stays `#[allow(<lint>, reason = "…")]` only where `expect` would be unfulfilled in some build. Examples: a `cfg` that removes the code, or a shared test module that one test crate uses fully and another only in part.
  - Each `reason` says what the exception prevents or why the lint is wrong there, in the comment style `CLAUDE.md` asks for. It is not a restatement of the lint's name.
- **The hot path:**
  - No cast rewrite adds a branch to a function the `codegen` gate holds to a budget (`xtask/src/codegen.rs`, `BUDGETS`) or to anything those functions inline.
  - No budget is raised. If one would have to be, stop and report it.
- **`ns-syntax`:** `crates/ns-syntax/src/lexer.rs` changes only in how it narrows offsets. Its tokens do not change, so `NewspeakLexer.kt` does not change.
- **Commits:** conventional commits, each ending with the session's `Co-Authored-By` and `Claude-Session` lines.
- **Gates:** every commit runs `cargo xtask gates commit` plus the groups `CLAUDE.md`'s table names for the files it touches:
  - `analyzer` for `crates/ns-analyzer`;
  - `images` for `image/`, `bytecode.rs` and `bytecode/`;
  - `caches` for `inline_cache.rs`;
  - `codegen` for `vm.rs`, `interpreter/mod.rs`, `interpreter/sends.rs`, `heap.rs`, `heap/frames.rs` and `bytecode/compact.rs`;
  - `memory` for `crates/ns-memory`.

  The batch ends with `cargo xtask gates end-of-batch`. A commit that never saw the end-of-batch gates is work in progress.
- **Subagents** run every command in the foreground.

## The forms a cast takes

Every site outside tests becomes one of these five forms. Choose by what bounds the value, not by what is shortest.

1. **Sign reinterpretation, deliberate** (`i64 as u64` of a bit pattern, a packed word): use `cast_unsigned()` / `cast_signed()`.
2. **A value bounded by an invariant, off the hot path:**
   - Use `<Target>::try_from(value).expect("internal: <the bound and who keeps it>")`. This is the form the codebase already uses, for example `compact.rs`'s `u32::try_from(self.wide.len()).expect("internal: a body holds at most INSTRUCTION_LIMIT instructions")`.
   - Allowed only where no program and no image can reach the panic.
   - `usize::try_from(u64)` compiles to nothing on a 64-bit target, so form 2 is the answer for `u64 as usize` wherever the bound is real on 32-bit targets too.
3. **A value bounded by an invariant, on the hot path:**
   - Use an `#[inline(always)]` helper beside the bound's owner.
   - The helper `debug_assert!`s the bound and carries the `#[expect(clippy::cast_possible_truncation, reason = …)]` that names it. One helper serves every site of that bound.
   - Helpers this plan fixes:
     - `heap/frames.rs`: `number_as_u32(word: Word) -> u32` and `number_as_usize(word: Word) -> usize`. Each is the `number_of` of a number word that holds an id, index or count of that width. These replace `frames::number_of(…) as u32` / `as usize`.
     - `heap/frames.rs`: `stack_offset(offset: usize) -> u32`. A stack offset is below `MAXIMUM_STACK_WORDS`, which the doc comment above it bounds to `u32`.
4. **Deliberate truncation to low bits** (a packed field, a hash folded to 32 bits, a `u128` product split into digits):
   - Use a named helper that says so, carrying the `#[expect]`. Examples: `RegisterRange`'s field accessors in `heap.rs` and `arbitrary_integer/`'s digit split.
   - In `arbitrary_integer/`, use `low_digit(value: u128) -> u64` and `high_digit(value: u128) -> u64`.
   - A single deliberate site may carry the `#[expect]` on its function instead.
5. **A value a program, an image or an editor decides:**
   - A narrowing here is never `expect`. It answers the error or `None` that the surrounding code already answers for an out-of-range value, through `try_from`.
   - If nothing bounds it, it is a defect: write a test that fails, fix it, and commit separately.
   - Known candidates:
     - `builtins/collections.rs:272/275/337/349` and `builtins/value.rs:120`: an `i64` index `as usize`, which wraps on a 32-bit target;
     - `symbol.rs:84`, the interner's `len() as u32`;
     - `ns-analyzer/src/documents.rs:24/46/55`: positions of a document an editor sent, which may not be lexed yet.

## Review Focus

1. **A program-decided `SmallInteger` used as an index on a 32-bit target.** A program is still refused an index past the collection's size.
   - Owner: Task 5.
   - Test: the golden `an_index_past_u32_is_refused`. It expects the same index error as for any out-of-range index.
2. **A `try_from(..).expect` that an image or program can reach** would turn a refusal into a panic.
   - Owner: each task. Every `expect` added in `image/`, `shipped_code/` or `builtins/` names the earlier check that bounds it.
   - Test: in Task 5, `cargo nextest run -p ns-runtime --test image_truncations` stays green, and so do the fuzz-style image tests.
3. **A hot-path helper that branches in a release build**, or a budget that drifts.
   - Owner: Task 4.
   - Test: `cargo xtask gates codegen`, with the same instruction counts as on `master` or fewer. Record both counts in the commit message.
4. **An `#[expect]` unfulfilled under a configuration the local clippy does not see:** the Linux and macOS `ns-memory` paths, or `cfg(debug_assertions)` code.
   - Owner: Tasks 1 and 7.
   - Test: `cargo xtask gates memory`, and `cargo clippy --workspace --all-targets --release` warning-free in Task 7.
5. **An LSP position past `u32::MAX` UTF-16 units in a document never lexed** answers a clamped position, not a panic.
   - Owner: Task 3.
   - Test: `documents::tests::a_position_past_u32_is_clamped`. It builds the line-start table of a synthetic text that the test describes by its line starts, not by four GiB of text.
