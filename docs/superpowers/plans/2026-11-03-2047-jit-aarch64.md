# The AArch64 encoder under QEMU Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Road step 8's last stage: the baseline JIT runs on AArch64 (Linux and Apple), its encoder checked against `yaxpeax-arm`, the suite run under `qemu-aarch64` in WSL2, and Linux x64 and AArch64 both gate groups at the end of a batch.

**Architecture:** `ns-assembler` gains a second `Encoder`, `Aarch64`, and two operations of the call convention that are empty or trivial on x64. The macro assembler assembles for either architecture through one `Encoding` enum chosen by the `Abi`. `Abi::Aapcs64` maps every role one to one from x64's. The native stack's slot size comes from the encoder, so stubs, the cut and the depth bound stop assuming eight bytes. A compiled frame keeps its return address in a 16-byte slot on `sp`, as V8 and HotSpot do.

**Tech Stack:** Rust 1.98.0; `yaxpeax-arm` 0.5 (dev-dependency of `ns-assembler` only, `0BSD`); WSL2 Ubuntu 22.04 with `qemu-user-static`, `binfmt-support`, `gcc-aarch64-linux-gnu`, and the rustup target `aarch64-unknown-linux-gnu`.

**Spec:** `docs/design/execution.md`, "Planned: the baseline JIT" ("The foundation and the one extension point", "Executable memory", "The native stack carries the return addresses", "Fixed registers and the calling convention", "Tests", "Stages") and the decisions below.

## Decisions

Decided with the user on 2026-11-03:

1. **The return address lies in a 16-byte slot on `sp`.** A call is `blr`. Every address a call reaches starts by storing `x30` there (`str x30, [sp, #-16]!`), and a return loads it back before `ret`. `sp` stays 16-byte aligned at all times, and each compiled activation costs 16 bytes of native stack. Prior art: V8 `EnterFrame` (`src/codegen/arm64/macro-assembler-arm64.cc:3109`) and HotSpot `build_frame` (`cpu/aarch64/macroAssembler_aarch64.cpp:5965-5973`). Rejected: Cog's second stack pointer (`cogitARMv8.c:345`, `:6359`).
2. **The disassembler is `yaxpeax-arm`**, a dev-dependency of `ns-assembler` only.
3. **`cfg(ns_jit)` is set for AArch64 on Linux and Apple.** Windows on ARM stays interpreted. The encoder never uses `x18` on any target, so there is one `Roles::of`.
4. **Two new gate groups, `linux` and `aarch64`**, both run in WSL. They belong to `end-of-batch` and run at the end of a batch that changed the runtime, never at each commit.

Proposed in this plan and open for review:

- **A conditional branch's long form is one `b.cond`** (4 bytes, ±1 MiB). Past that reach, `finish` answers `BranchOutOfReach` and the body stays interpreted, as any other assembly failure leaves it. The alternative, an inverted `b.cond` over a `b`, turns every forward check on the hot path into a taken branch. HotSpot's AArch64 back end also assumes `b.cond` reach inside a method.
- **Contents of `linux`:** `cargo xtask shipped-code`, clippy over the workspace, the default suite and the doctests. **Contents of `aarch64`:** the same cross-compiled for `aarch64-unknown-linux-gnu`, the suite run through binfmt's `qemu-aarch64` with `RUST_MIN_STACK=8388608`, the doctests not run. Neither group runs a stress mode.

## Global Constraints

- Every encoding constant of `ns-assembler` is a named `const`, its doc comment citing the developer.arm.com page of the instruction. No integer literal other than 0 and 1 stands outside a `const` (`tests/encoding_sources.rs` walks `src/` and so covers `aarch64.rs` automatically).
- No file under `crates/ns-runtime/src/jit/` except `macro_assembler.rs` names `x64` or `aarch64` outside a test module (`tests/jit_architecture_split.rs`, extended in Task 5).
- x64 machine code is byte-identical before and after this batch: the new operations encode as nothing (`EnterCalled`) or as the old `jmp` (`JumpIntoCalled`), and x64's slot size stays 8.
- `ns-assembler` forbids `unsafe`. `ns-memory` remains the only crate with `unsafe`.
- Names are written out (CLAUDE.md, "Conventions"), including test names and the registers' constants (`X0` … `X30` are names bound to the architecture and allowed).
- Every commit runs `cargo xtask gates commit`. The batch ends with `cargo xtask gates end-of-batch`, which now includes `linux` and `aarch64`.
- Goldens are not touched. A golden that fails under QEMU is a defect of the port.

## Review Focus

1. **A test thread with too little native stack silently runs interpreted**, so the QEMU suite would test nothing of the JIT. The AArch64 bound is about 1.68 MB, close to a test thread's 2 MiB. Expected: the `aarch64` group sets `RUST_MIN_STACK=8388608`, and `the_jit_is_available_on_its_architectures` plus one in-process run assert machine entries > 0 under AArch64 (Task 5, Task 7).
2. **A stub that tail-jumps into an entry saves the return address twice**, which shifts every walk by 16 bytes, so a materialization or a cut reads the wrong frame. Expected: every jump into a call target uses `jump_into_called`, and the exit, cut and miss paths run under QEMU through the goldens and the `CALL_EXIT`/`EXIT_AT_POLL` stress-mode tests in the default suite (Task 4, Task 7).
3. **An operand register the encoder reserves** (`x16`, `x17`, `x18`, `x30`) is used by a role, which corrupts a synthesized sequence. Expected: the encoder panics on such an operand, and the cross-assembly test assembles every stub and every golden body for `Abi::Aapcs64` on Windows (Task 2, Task 5).
4. **Code or data that is not 4-aligned for AArch64**, or a `ldr` literal to a data word whose distance is not a multiple of 4. Expected: `Assembled::alignment` is at least 4 under `Aarch64`, and `encode_label_reference` answers `false` for a distance that is not a multiple of 4 (Task 3).
5. **`sp` as an operand where its encoding means `xzr`** (`and`, `cmp` with `sp` on the right, `mov` to or from `sp`). Expected: those forms go through `x16`, and the disassembly test pins each of them (Task 2).

### Task 2: The AArch64 encoder: moves, memory, arithmetic, logic, compares

**Files:**

**Interfaces:**
- Produces: `pub struct Aarch64;` (`Default`); `pub const X0 … X30: Register` (numbers 0–30); `pub const SP: Register = Register(31)`, the stack pointer, never `xzr`. Reserved for the encoder and refused as an operand by a panic: `X16`, `X17` (the encoder's scratch registers), `X18` (the platform register), `X30` (the link register, owned by the convention). `stack_slot_bytes() == 16`, `instruction_alignment() == 4`.
- Consumes: Task 1's trait.

Encodings this task pins (the remaining operations panic with `todo!` until Task 3):
- `MoveRegister`: `mov xd, xn`, or `mov` to or from `sp` through `add #0`. `MoveImmediate`: the shorter of a `movz` sequence and a `movn` sequence (`movk` per remaining halfword, at most four instructions in total). `MoveIf`: `csel xd, xn, xd, cond`.
- `Load` / `Store` by width (`ldrb`/`ldrh`/`ldr w`/`ldr x`, the same for stores). The scaled unsigned `imm12` form when it fits, else `ldur`/`stur` for −256…255, else the displacement into `x16` and the register-offset form. `StoreImmediate32`: `str xzr` for 0, else the value into `x17` and stored.
- `Add`/`Subtract`: `adds`/`subs`. `AddImmediate`: `adds`/`subs #imm12`, the `lsl #12` form when it applies, else through `x16`. `AddStack`: `add`/`sub sp, sp`, through `x16` beyond `imm12`. A flag-setting operation on `SP` panics.
- `And`: `and`. `AndImmediate`/`OrImmediate`: the logical bitmask immediate when encodable, else through `x16`. A target of `SP`: `mov x16, sp` first, then `and sp, x16, #imm`. `ShiftLeft`/`ShiftRightLogical`/`ShiftRightArithmetic`: `lsl`/`lsr`/`asr` as aliases of `ubfm`/`sbfm`.
- `Compare`: `cmp`, `sp` on the right through `x16`. `CompareImmediate`: `cmp`/`cmn #imm12`, else through `x16`. `CompareMemory`: the word loaded into `x17`, then `cmp`. `TestImmediate`: `tst` with a bitmask immediate (`w` form for `Word32`), else through `x16`.
- The condition codes: `Equal` eq, `NotEqual` ne, `Less` lt, `LessOrEqual` le, `Greater` gt, `GreaterOrEqual` ge, `Below` lo, `BelowOrEqual` ls, `Above` hi, `AboveOrEqual` hs, `Overflow` vs, `NoOverflow` vc.

### Task 3: The AArch64 encoder: control flow, the stack, multiply, divide, references, stops

**Files:**
- Modify: `crates/ns-assembler/src/aarch64.rs`
- Test: `crates/ns-assembler/tests/aarch64_encodings.rs`

**Interfaces:**
- Produces: the rest of `Encoder` for `Aarch64`; after this task no operation panics with `todo!`.

Encodings:
- `CallRegister`: `blr`. `JumpRegister`: `br`. `EnterCalled`: `str x30, [sp, #-16]!`. `Return`: `ldr x30, [sp], #16` then `ret`. `JumpIntoCalled`: `add x16, target, #4` then `br x16`. `Push`: `str x, [sp, #-16]!`. `Pop`: `ldr x, [sp], #16`.
- `MultiplyChecked`: the four instructions `lib.rs`'s flag contract already documents (`smulh x16`, `mul`, `cmp x16, target, asr #63`, `ccmp xzr, xzr, #0b0001, eq`). `DivideSigned`: `sdiv x16, dividend, divisor`, then `msub remainder, x16, divisor, dividend`, then `mov dividend, x16`. Any three distinct registers are accepted, and equal ones panic.
- `LoadCodeAddress`: `adr target, #4`. `LabelReference::Load`: `ldr x, literal`. `LabelReference::Address`: `adr`. Each is 4 bytes and reaches ±1 MiB; a distance outside that, or one that is not a multiple of 4, answers `false`.
- Branches: `Short` and `Long` unconditional are both `b` (±128 MiB). Conditional `Short` and `Long` are both `b.cond` (±1 MiB), since the plan's proposal makes the long form 4 bytes too. A distance out of reach or not a multiple of 4 answers `false`.
- `Trap`: `udf #0`. `fill_with_stops`: zero words (`udf #0`); a length that is not a multiple of 4 panics.
