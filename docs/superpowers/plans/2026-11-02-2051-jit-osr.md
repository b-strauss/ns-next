# Road step 8, stage 5: on-stack replacement, the polls and the depth count Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An interpreted frame switches into its body's machine code at a
backward jump, so that a hot loop in a body entered once runs compiled; a
frame that left its machine code at a poll goes back into it once the
safepoint is served; a compiled push checks the depth and a safepoint
request with one compare; the share of a run the baseline compiler takes
is counted; and whether the depth count lives in a machine register is
measured.

**Architecture:** The frames already share one format and every body
already maps every program counter to its machine code
(`ProgramCounterMap::machine_offset`, `jit/mod.rs:601`), which
`entry_of_frame` and `run_machine_code` use for a frame returned to. So
on-stack replacement is a trigger, not a conversion: a counter of back
jumps beside the entry count in `JitSlot`, one new out-of-line function
`jit::at_back_edge` the interpreter's backward jump calls while the
body's slot is armed, and the same function called once after a
safepoint the stretch left for at a loop's head. The poll folds into the
depth limit word, which a real request lowers to 0.

**Tech Stack:** Rust 1.98.0, edition 2021; no new dependency.

**Spec:** `docs/design/execution.md`, "When a body is compiled" (the
counter, the threshold, synchronous compilation, decided with the user on
2026-11-02), "Between the tiers" (the switch, and the return into machine
code after a poll's exit, decided 2026-11-02), "Safepoints and the depth
limit" and "Polls and the depth check" (decided 2026-10-27).

## Global Constraints

- `unsafe` only in `ns-memory`; names written out (`CLAUDE.md`,
  Conventions); machine code holds no handle; the JIT compiled in only
  where `cfg(ns_jit)`; `NS_NEXT_NO_JIT=1` turns it off.
- `vm.rs` holds no dispatch logic: its backward jump only asks
  `JitSlot::back_edge_is_armed()` and calls `jit::at_back_edge`; what
  happens there is `jit/`'s.
- The interpreter's hot path gains at most one load and one compare per
  backward jump that found no safepoint requested; everything else is
  `#[cold] #[inline(never)]`.
- No word machine code reads lies in the `Mutator` (`heap/machine_words.rs`).
- The goldens' outcomes do not change, and neither does where a recursion
  overflows: the depth count stays exact.
- A body the JIT refused, abandoned or found exiting at once is never
  entered by a back edge; a top-level activation is never entered
  (`jit::entered`'s refusal).
- New tests in `crates/ns-runtime/tests/jit.rs` use its helpers
  (`load_with`, `run_measured`, `since`, `for_each_lowering!`), and
  `since` gains every new statistic.
- Commits: conventional, each ending with the `Co-Authored-By:` line
  naming the committing model and the session's `Claude-Session:` line.
- Gates: `cargo xtask gates commit` before every commit; `codegen` too for
  Tasks 1-3 (they touch `vm.rs` or `heap.rs`); `end-of-batch` in Task 5.
  A commit that never saw the end-of-batch gates is work in progress, and
  a subagent implementing a task is told so.

## Review Focus

- A loop whose body exits on every turn (an `ifTrue:` sent to a block in
  a variable): the switch at every back jump must not ping-pong without
  bound -- the exit budget abandons the body, and an abandoned body is not
  armed. Test in Task 1.
- A frame the interpreter reified (a block created in the loop captured
  it) switches into the twin, never the lean body. Test in Task 1.
- A block activation with a loop, entered once: it switches, and its
  machine entry row is written as a push's would be. Test in Task 1.
- The stress modes' held request (`STRESS_HOLD`) must not lower the depth
  limit word, or compiled frames stop nesting under every stress mode.
  Test in Task 3.
- The depth reserve held (`Mutator::set_depth_reserve`) while a request is
  pending, and released while one is: the word ends as `limit` or 0 by
  the request alone. Test in Task 3.

- [ ] **Step 3: Build the register variant** in a commit of its own: the

  `Roles::of_abi`'s doc comment and `execution.md`'s "`r13` plays no role

  whatever the measurement decides: two registers play no role, `r13`
  and `rbp`. A new role `Roles::depth`
  loaded by the entry stub, compared and incremented by the prologue,
  decremented by the return, written back to `DepthCount` before every

  `NS_NEXT_STRESS_EXIT` must pass unchanged.
