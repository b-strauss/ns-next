# The entry into machine code at its cost Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every compiled body runs in machine code wherever it runs: an
interpreter's send calls a compiled callee as a compiled send does, every
other entry crosses a bridge prepared once, and `jit::CALLED_ONLY` goes,
so that a recursion rooted in an interpreted frame without a loop --
`fib: 20` sent once from a host -- runs in machine code.

**Architecture:** Two parts, which the decision combines. The bridge
(`jit::entered`, `jit::resumed`, `run_machine_code`) keeps its entry
block beside the machine words, outside the mutator, writing the words
that name the zone and the caches only when those change, and stops
counting, searching and building what a compiled body's entry does not
need. The call (`jit::called`): when a send decided a method's
activation on its own slots and the body has machine code in this zone,
the interpreter hands the receiver and the defining class over in the
machine words and calls the body's machine entry through a new call
stub; the prologue builds the frame, the callee's `ret` delivers the
value into the send's destination, and an exit's walk starts from the
sender's send, seeded before the call.

**Tech Stack:** Rust 1.98.0, edition 2021; no new dependency.

**Spec:** `docs/design/execution.md`, "Planned: the baseline JIT", "The
entry at a send" (decided with the user on 2026-10-29), with "The
baseline JIT's foundation", "Sends, returns and the exit that
materializes" and "The machine words", which it builds on.

## Global Constraints

- `unsafe` only in `ns-memory`; names written out (`CLAUDE.md`,
  Conventions); machine code holds no handle; code written only through
  `CodeWriter`; the JIT compiled in only where `cfg(ns_jit)`;
  `NS_NEXT_NO_JIT=1` turns it off.
- `vm.rs` holds no dispatch logic: whether a decided step is called in
  machine code is decided in `interpreter/` and `jit/`; `vm.rs` only
  delivers what the send answers.
- No word machine code reads or writes between two leaf calls lies in the
  `Mutator`: the persistent entry block is an allocation of its own,
  shared as `Rc` of `Cell`s, like the machine words
  (`heap/machine_words.rs`), never a `Box` and never a field of a struct
  inside the mutator.
- Machine code is a lowering of the interpreter's instructions: the call
  stub does what `Mutator::push_sent` and the callee's run do, nothing
  more; a call the prologue refuses is pushed by the interpreter's own
  push, which raises the overflow or grows the stack.
- A leaf runs no Newspeak code, cannot collect, reads no other activation
  and never pushes.
- The goldens' outcomes do not change; where a recursion overflows does
  not change: the call counts exactly as the interpreter's push does.
- A new golden's `.toml` is recorded with `NS_NEXT_NO_JIT=1`.
- Commits: conventional, each ending with the `Co-Authored-By:` line
  naming the committing model and the session's `Claude-Session:` line.
- Gates: `cargo xtask gates commit` before every commit; also `memory`
  for Task 1 (it touches `crates/ns-memory`), `codegen` for Task 2 (it
  touches `vm.rs` and `interpreter/mod.rs`); `end-of-batch` in Task 4. A
  commit that never saw the end-of-batch gates is work in progress, and
  a subagent implementing a task is told so.
- Never judge performance from a debug build; every timing follows the
  `measuring-performance` skill. Ask the user before any run of minutes.

## Review Focus

1. **A recursion rooted in an interpreted frame that overflows the depth
   limit** -- the call's prologue refuses at the limit and the
   interpreter's push must raise there, at the same activation and with
   the same stack trace as without the JIT; Task 2's golden
   `goldens/runtime/jit/interpreted_root_recursion.ns` pins it.
2. **An exit inside a callee the interpreter called** -- every compiled
   frame above the interpreted sender must be materialized, the callee
   first, and the sender must go on after the send with the callee's
   value; Task 2's
   `an_exit_in_a_called_body_materializes_it_above_its_interpreted_sender`
   pins it.
3. **A safepoint requested while the interpreter is about to call** --
   the prologue refuses, the interpreter pushes, and the collection runs
   at the next switch exactly as without the JIT; Task 2's step 4 runs
   every golden under `NS_NEXT_STRESS_SCAVENGE=1` and
   `NS_NEXT_STRESS_EXIT=1` together.
4. **The global cache resized between two entries** -- the persistent
   block must name the new mask; Task 1's
   `the_entry_block_follows_a_resized_global_cache` pins it.
5. **A send whose arguments the decision read from consecutive sources
   rather than the slots** -- the call must place them into the slots
   first, as `push_on_slots` does; Task 2's golden
   `goldens/runtime/jit/called_arguments_from_sources.ns` pins it.

## File Structure

- `crates/ns-memory/src/code_zone.rs`: `EntryBlock`, the shared block of
  `ENTRY_BLOCK_WORDS` cells; `CodeZone::enter` takes it.
- `crates/ns-runtime/src/jit/mod.rs`: the bridge's block in `JitState`,
  the trimmed `entered`, `resumed` and `run_machine_code`, `called` and
  `Called`, the slot without `CALLED_ONLY`.
- `crates/ns-runtime/src/jit/stubs.rs`: `assemble_call_stub`.
- `crates/ns-runtime/src/jit/materialize.rs`: the walk's seed.
- `crates/ns-runtime/src/jit/leaves.rs`: the leaf table built once.
- `crates/ns-runtime/src/interpreter/mod.rs`: `Mutator::enter_sent` and
  `Sent`.
- `crates/ns-runtime/src/vm.rs`: `deliver` delivers a `Sent`.
- `crates/ns-runtime/tests/jit.rs`, `goldens/runtime/jit/`,
  `benchmarks/micro/bench_recursion.ns`: the tests, goldens and the
  microbenchmark.

### Task 1: The bridge, prepared once

**Files:**
- Modify: `crates/ns-memory/src/code_zone.rs` (`enter`, a new
  `EntryBlock`), `crates/ns-memory/src/lib.rs` (its export),
  `crates/ns-runtime/src/jit/mod.rs` (`JitState`, `JitSlot`, `entered`,
  `run_machine_code`, `interpreter_entry`), `crates/ns-runtime/src/jit/leaves.rs`
  (`table`), whatever resizes the global cache
  (`interpreter/inline_cache.rs`) to mark the block stale
- Test: `crates/ns-memory/src/code_zone.rs` (its tests module),
  `crates/ns-runtime/tests/jit.rs`

**Interfaces:**
- Produces:
  - `ns_memory::EntryBlock`: `EntryBlock::new() -> EntryBlock` (all
    words 0), `get(&self, index: usize) -> u64`,
    `set(&self, index: usize, word: u64)`, `Clone` sharing the one
    allocation (`Rc<[Cell<u64>; ENTRY_BLOCK_WORDS]>`). Machine code
    writes it through the pointer `enter` hands it, which is sound
    because every word is a `Cell`.
  - `CodeZone::enter<C>(&self, stub: CodeOffset, block: &EntryBlock,
    context: &mut C, leaves: &[Leaf<C>]) -> u64`, writing words 0 to 3
    as today.
  - `JitState::block: EntryBlock` and `JitState::block_stale: bool`;
    `JitState::mark_block_stale(&mut self)`, called wherever a word the
    block holds changes: a zone made or replaced, the global cache
    resized. The words written only when stale: `ObjectSpaceBase`,
    `StackBase`, `MachineWords`, `ExitStub`, `Cells`, `PolymorphicStub`,
    `PolymorphicBlocks`, `GlobalRows`, `GlobalMask`. The words written at
    every entry: `RegisterBase`, `MachineEntry`, and when counting
    `BackEdges` and `CompiledCalls` set to 0.
  - `JitSlot` records the machine offset of program counter 0 beside
    `offset`, so `interpreter_entry(code, feedback_base, 0)` answers
    without `ProgramCounterMap::machine_offset`.
  - `entered` calls `note_entry` and `Heap::activation_method` only for
    a slot still counting or compiled into another zone.
  - `leaves::table` answers a `&'static` table, or the table is built
    once per `JitState`; `run_machine_code` builds none.
  - `run_machine_code` decodes `ExitKind::Returned` first and returns
    before the exit's bookkeeping (the send-exit count, the exit budget,
    `clear_compiled`), which a return never needs.

### Task 2: An interpreter's send calls compiled code

**Files:**
- Modify: `crates/ns-runtime/src/jit/stubs.rs` (`assemble_call_stub`),
  `crates/ns-runtime/src/jit/mod.rs` (the zone's `call_stub`, `called`,
  `Called`, `JitStatistics::called_entries`),
  `crates/ns-runtime/src/jit/materialize.rs` (the seed),
  `crates/ns-runtime/src/interpreter/mod.rs` (`enter_sent`, `Sent`),
  `crates/ns-runtime/src/vm.rs` (`deliver`), `CLAUDE.md` (the invariant
  "Machine code is a lowering…": the run loop enters machine code
  through `jit::entered`, `jit::resumed` and, at a send, `jit::called`)
- Create: `goldens/runtime/jit/interpreted_root_recursion.ns` and
  `.toml`, `goldens/runtime/jit/called_arguments_from_sources.ns` and
  `.toml`
- Test: `crates/ns-runtime/tests/jit.rs`

**Interfaces:**
- Consumes: Task 1's `EntryBlock` and the prepared block.
- Produces:
  - `stubs::assemble_call_stub(abi: Abi) -> Assembled`: as the entry
    stub -- saves the callee-saved registers, pins the roles from the
    block, saves the stack pointer -- and also loads `callee_receiver`
    and `callee_class` from machine words `CalleeReceiver` and
    `CalleeClass` and sets `send_cells` to 0, as the miss stub hands a
    callee over; calls `MachineEntry`, the body's machine entry (its
    prologue); on return stores the value and `ExitKind::Returned` and
    does **not** add one back to `DepthCount`, since nothing pops the
    callee. An exit inside leaves through the exit stub unchanged.
  - `jit::Called` (`pub(crate) enum`): `Refused` -- the prologue refused
    before the callee's frame was written, or the body has no machine
    code here, or the native stack has too little room: push it in the
    interpreter; `Returned { value: u64 }`; `Stopped(Resumption)` -- an
    exit above, where the run loop goes on (`Interpreted` or
    `Safepoint`), the innermost frame the walk materialized.
  - `jit::called(mutator: &mut Mutator<'_>, sender: ActivationReference,
    register_base: RegisterBase, argument_base: u16, receiver: Value<'_>,
    defining_class: ClassReference<'_>, code: &Rc<CompiledCode>,
    feedback_base: FeedbackBase) -> Called`, `#[cold]`, out of line:
    looks up the body's machine entry (`machine_entry_address`), checks
    the room, writes the machine words, seeds the walk (below), sets the
    block's `RegisterBase` to the sender's register base plus
    `argument_base` and `MachineEntry`, enters the call stub, counts
    `called_entries`, and maps the exit as `run_machine_code` does --
    a `PushRefused` with nothing walked is `Refused`.
  - The walk's seed: `materialize::Walk::seed_call(&mut self, sender
    header offset, argument base, top)` sets `callee` as a compiled
    sender's send would, so `materialize_frame`, `materialize_innermost`
    and `leaf_frame` take the callee's frame as the walk's first, its
    caller the interpreted sender; an entry at a push leaves the seed
    empty and starts at the entry's frame as today.
  - `Mutator::enter_sent(&mut self, step: Step<'gc>, send_arguments:
    Arguments<'_, 'gc>, sender: Option<ActivationReference>, inlinable:
    bool, slots: Option<u16>) -> Result<Sent<'gc>, Signal<'gc>>` in
    `interpreter/mod.rs`, with `pub(crate) enum Sent<'gc> { Value(Value<'gc>),
    Pushed(ActivationReference, usize), Stopped(Resumption) }`: for a
    `Step::Method` with `StepArguments::Send` on `Some(slots)` whose
    body's `JitSlot` says compiled in this zone, it checks the arity as
    `push_step_placed` does, places the arguments into the slots when the
    window is not the slots (`Heap::place_in_slots`), resolves the
    feedback base as the push does, and calls `jit::called`; `Refused`
    and every other step go to `push_sent` (`Pushed`). The test of the
    slot is one load and one compare, inline; the rest is out of line.
  - `vm::deliver` matches `enter_sent`'s answer: `Value` into the
    destination and `Transfer::Next`, as a decided value; `Pushed` as
    today; `Stopped` switches to the innermost frame or leaves for the
    safepoint as `machine_code_switch` does for a `Resumption`.
