# Sends and the caches in machine code Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Road step 8's third stage on x64: a compiled body calls a
compiled body through the cell of its send's cache entry and is returned
to by `ret`, so that a body's machine code runs through its sends and its
return instead of exiting at its first send.

**Architecture:** The caches stay Rust data; every entry gets a
machine-readable cell in a reservation of its own, written wherever the
entry is. A send's template computes the receiver's guard, compares it
with the cell's and calls through the cell's entry address -- a callee's
machine entry, a stub for a non-method target, the polymorphic or the
megamorphic stub, or the miss stub, whose leaf resolves, fills and
compiles. The return addresses of nested compiled frames are on the
native stack; their words are at the interpreter's positions on the
activation stack, the receiver and current class written by the call, the
rest of the header by the exit, which walks the return addresses and
materializes every compiled frame before the run loop or any observer
runs.

**Tech Stack:** Rust 1.98.0, edition 2021; no new dependency.

**Spec:** `docs/design/execution.md`: "Planned: the deoptimization
contract" (as amended on 2026-10-28: the call writes the receiver and the
current class), "Planned: the baseline JIT", "Inline caches" and "Sends
in machine code"; the seven decisions there were taken with the user on
2026-10-28.

## Global Constraints

- Everything of the foundation's plan's Global Constraints holds
  (`docs/superpowers/plans/2026-10-27-2047-baseline-jit-foundation.md`):
  `unsafe` only in `ns-memory`; names written out; machine code holds no
  handle; code written only through `CodeWriter`; JIT compiled in only
  where `cfg(ns_jit)`; `NS_NEXT_NO_JIT=1` turns it off; `vm.rs` holds no
  dispatch logic.
- "A cache records what the lookup decided; it never decides": a cell is
  written only from its entry, in the same function that writes the
  entry; a cell's entry address is a function of the entry's `Target`
  alone.
- Machine code is a lowering of the interpreter's instructions: a stub
  for a target does what `Mutator::act_with_base` does for it, nothing
  more, and every target a stub does not cover exits so the interpreter
  runs the send.
- No word machine code reads or writes between two leaf calls lies in the
  `Mutator`: cells in their reservation, counts and bounds in the machine
  words (`heap/machine_words.rs`).
- A leaf runs no Newspeak code, cannot collect, reads no other activation,
  never pushes; the miss leaf may compile and install, nothing else may.
- The goldens' outcomes do not change. Where a recursion overflows, which
  the goldens pin, does not change: a compiled push counts exactly as the
  interpreter's.
- Commits: conventional, each ending with the `Co-Authored-By:` line
  naming the committing model and the session's `Claude-Session:` line.
- Gates: `cargo xtask gates commit` before every commit; also `images`
  for Task 1, `caches` for Tasks 1 and 3, `memory` for Task 4, `codegen`
  for every task touching `vm.rs`, `interpreter/mod.rs`,
  `interpreter/sends.rs`, `heap.rs` or `heap/frames.rs`; `end-of-batch`
  after Task 10. A commit that never saw the end-of-batch gates is work
  in progress, and a subagent implementing a task is told so.

## Review Focus

1. **A method found at a level a mixin applied twice adds, run as
   machine code** -- its `super` and its lexical sends must start from
   the level the lookup found, not the first application of the mixin;
   Task 6's golden `goldens/runtime/jit/mixin_applied_twice.ns` pins it.
2. **A recursion through compiled sends overflowing the depth limit** --
   it must raise at the activation the interpreter raises at, with the
   same stack trace, and a handler near the limit must run in the
   reserve; Task 5's golden `goldens/runtime/jit/send_recursion_overflow.ns`
   pins it.
3. **A receiver the bulk forward replaced while a compiled frame holds a
   cell hit for it** -- the next send must miss or take the slot guard's
   cold check, never read the old layout; Task 8's
   `a_getter_stub_after_a_forward_reads_the_new_layout` pins it.
4. **A collection requested from inside a deep stretch of compiled
   frames** -- every frame must be materialized before the collector
   traces the stack and resume in machine code afterwards; Task 5's run
   of every golden under `NS_NEXT_STRESS_EXIT` with
   `NS_NEXT_STRESS_SCAVENGE` pins it.
5. **An edit installed while compiled callers hold cells naming the edited
   method** -- after the install every send reaches the new method;
   Task 3's `an_install_vacates_every_cell` pins it.

## File Structure

- `crates/ns-memory/src/native_stack.rs` (new): the running thread's
  native stack bounds, per platform.
- `crates/ns-runtime/src/interpreter/inline_cache/cells.rs` (new): the cell

  the one writer of each.

  entry writes its cell; `SendInlinable` cached; the miss as a decision
  machine code can call.

  `heap/frames.rs`: the depth count, the depth limit, the ordinary

  callee's prologue.

  the native stack.

  `MachineCall`.
- `crates/ns-runtime/src/vm.rs`: the exits' new `Resumption`s, resuming a
  compiled frame in machine code.

### Task 3: The cells

**Files:**
- Create: `crates/ns-runtime/src/interpreter/inline_cache/cells.rs`
- Modify: `crates/ns-runtime/src/interpreter/inline_cache.rs`
  (`advance`, `forget_families`, `invalidate`, `forget_freed`,
  `GlobalCache::insert`/`clear`/`retain`), `crates/ns-runtime/src/jit/mod.rs`
- Test: `crates/ns-runtime/tests/inline_caches.rs`, unit tests in `cells.rs`

**Interfaces:**
- Produces:
  ```rust
  #[repr(C)]
  pub(crate) struct Cell { guard: u64, entry: u64, level: u64, chain_start: u64 }
  pub(crate) enum ChainStart { ReceiverClass = 0, LexicalClass = 1, Superclass = 2 }
  pub(crate) struct Cells { /* an ns-memory Reservation, 1 GiB, committed as it grows */ }
  impl Cells {
      pub(crate) fn site_address(&self, index: usize) -> usize;
      pub(crate) fn block_address(&self, block: u32) -> usize; // four cells
      pub(crate) fn global_address(&self) -> usize;            // the mirror's groups
  }
  pub(crate) fn jit::cell_entry(state: &JitState, target: &Target) -> u64;
  ```
  A cell's `guard` is the entry's `DispatchId` for a public site and a
  non-private lexical one; for a `super` site and a private lexical one it
  is the key class's `class_field::APPLICATION` word, the application index
  that determines the entry's guard, so machine code compares a word of
  the class object it found. `level` and `chain_start` say where
  `current_class` is found: `level` superclass steps from the chain's
  start. A global mirror row is `{guard, selector, rule, entry, level,
  chain_start}`, eight words with padding, at the same group and way as
  its `GlobalEntry`. `cell_entry` answers the miss stub's address for
  every target until Tasks 5, 7 and 8 give targets their own; 0 where
  there is no zone.

### Task 5: A public send to a compiled method, its return, and the exit that materializes

**Files:**
- Create: `crates/ns-runtime/src/jit/sends.rs`, `crates/ns-runtime/src/jit/materialize.rs`
- Modify: `jit/baseline.rs` (the `SendPublic`, `SendInlinable`, `Return`,
  `ImplicitReturn` arms), `jit/macro_assembler.rs`, `jit/stubs.rs`,
  `jit/leaves.rs`, `jit/mod.rs`, `vm.rs`, `heap.rs`, `heap/frames.rs`
  (the compiled bit in the flags word, bit 26, the debug generation moving
  to 27-57)
- Test: `crates/ns-runtime/tests/jit.rs`, `goldens/runtime/jit/`

**Interfaces:**
- Consumes: Task 2's machine words, Task 3's `Cells` and `Cell`, Task 4's
  `body_at` and `program_counter_of_return`.
- Produces:
  - Idioms: `load_guard(target, value_register)` (header word's low 22
    bits, or `ImmediateGuard` by tag), `load_class(target, value_register)`
    (the class word, or `ImmediateClass` by tag), `walk_superclasses(class_register, level_register)`.
  - The call sequence: spill nothing (stage 3 keeps every value in its
    slot); load the receiver from its slot, its guard, the cell's address
    (the cell table's base from block word `Cells`, 15, plus
    `(feedback_base + site) * 32`, `feedback_base` embedded: a method
    body's base is assigned before its second entry); compare the guard
    with the cell's, on a mismatch call the polymorphic stub's address
    from block word `PolymorphicStub`, 16 (until Task 7, the miss stub);
    on a hit compute the current class from the cell's `level` and
    `chain_start`, store the receiver and it into the callee's header
    places 0 and 1 (the callee's frame begins at the send's argument
    base), add `argument_base * 8` to `rbx`, `call [cell.entry]`, subtract
    it again, store `rax` into the destination.
  - The callee's machine entry (`ProgramCounterMap::machine_entry`,
    distinct from its offset 0 which the interpreter's entry uses): exit
    (`ExitKind::PushRefused`, the caller re-executes the send) unless
    `DepthCount < DepthLimit`, the frame's end `<= OrdinaryStackEnd` and
    no safepoint is requested; increment `DepthCount`; fill the named
    locals with nil; in a debug build write the poison into the scratch
    registers and the flags word with a generation from machine word
    `NextGeneration`.
  - `Return`: decrement `DepthCount`, load the value into `rax`, `ret`.
    The entry stub's `call` of the body is followed by the return path:
    it writes `ExitKind::Returned` and the value (block word 8) and
    returns to `enter`'s caller, so the bottom frame of an entry returns
    through the run loop's `finish`.
  - The miss leaf `Leaf::Miss` (`arguments`: the caller's activation word,
    the send's program counter): runs `inline_cache`'s decision for the
    send without acting -- `inline_cache::decide_at(mutator, activation,
    program_counter) -> MissAnswer` -- which resolves and fills exactly
    as `miss` does, counts the callee's entry with `jit::note_entry` and
    answers the cell's entry address to jump to, or `EXIT` when the target
    has no stub and no machine code; the stub then exits
    (`ExitKind::Reexecute`) at the send.
  - `jit::materialize::walk(mutator, block) -> ActivationReference`:
    from the entry's activation up, each return address on the native
    stack between the saved and the current stack pointer names the
    caller's send (`body_at`, `program_counter_of_return`), the send's
    argument base the callee's frame; it writes each compiled frame's
    header but places 0 and 1 -- code, program counter, operand, flags
    with the compiled bit, feedback base, caller, continuation nil, guard
    and entered level none, register count, reified nil -- sets the frame
    stack's top and innermost, and answers the innermost activation.
  - `Resumption::{Interpreted, Safepoint}` carry the activation;
    `vm::resume_caller` enters machine code at
    `machine_offset(program_counter + 1)` when the caller's flags word
    has the compiled bit and its body has machine code in this zone, else
    clears the bit and interprets.
