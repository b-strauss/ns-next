# Implementation plans

These are **execution records**, not living documents. Each plan describes the
work of one milestone as it was planned and carried out, and is left as written
once complete — including its dated filename, `YYYY-MM-DD-HHMM-<name>.md`, so
several from one day sort chronologically.

Two things follow from that, and are expected rather than defects:

- **A plan can cite a spec file that no longer exists.** The dated design specs
  under `docs/superpowers/specs/` were folded into the living documents in
  [`docs/design/`](../../design/README.md) on 2026-09-07 and removed. Git holds
  the originals; the current design is in `docs/design/`.
- **A plan can use the old milestone numbering.** Language completeness was
  pulled ahead of the performance work on 2026-09-06, which renumbered
  everything after M2. Plans written before that date say "Milestone 3" where
  the schedule now says M4.

For what the system does today, read `docs/design/`. For when each milestone
landed, read `docs/PROGRESS.md`.
