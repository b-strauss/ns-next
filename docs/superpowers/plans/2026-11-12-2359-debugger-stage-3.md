# Debugger Stage 3: Breakpoints and Stepping — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A program run under the debugging API stops at line breakpoints (pending ones included), method breakpoints and exception breakpoints, and steps over, into and out by statement -- shipped code filtered -- and to a cursor, at full speed in machine code everywhere but in the bodies a breakpoint or a step patched.

**Architecture:** A breakpoint replaces one slot of a body's `EncodedBody::slots` (now `Cell`s) by the compact-only `CompactInstruction::Breakpoint` and keeps the original beside the slots; the decoded view, `send_destination` and every other reader see the original, and only the run loop's fetch sees `Breakpoint`, whose cold arm asks `interpreter/` whether to stop and otherwise re-dispatches the original through its ordinary arm. Patching frees the body's machine code and every optimized copy that inlined it, the baseline lowers a patched index as an exit, and the optimizing tier refuses a patched body. Steps are one-shot breakpoints -- the stepping frame's statement starts and its caller's return point, carried for one activation by its position -- plus a held safepoint request for a step into, the unwinder's and the non-`Deliver` continuations' reports for the frames that leave otherwise, and the step filter that turns a stop in shipped code into a step into. Exceptions stop through two new mirror leaves in `Kernel.ns`.

**Tech Stack:** Rust 1.98.0 (edition 2021), `cargo-nextest`; Newspeak (`Kernel.ns`); no new dependency.

**Spec:** `docs/design/debugger.md` -- decisions 2, 3, 4, 16 and 17; "Planned: the mechanisms": "Where the original lives", "A breakpoint in a method with a fast path", "Stopping at and going past a breakpoint", "Breakpoints by body, and reclaimed code ids", "A breakpoint names a source position", "Step over in recursion and blocks", "Step into's held request", "Exceptions", "Method breakpoints", "The return value of the last call"; "Testing and gates" (the two planned stress modes, the planned codegen check); "Planned: the order of building it", stage 3.

## Global Constraints

- `ns-runtime` forbids `unsafe`; no new external dependency. Names are written out (`CLAUDE.md`, Conventions).
- Never `{:?}` a `Value`, never `.unwrap()`/`.expect()`/`{:?}` an `EvaluationResult`; tests use the local `expect_ok` of `tests/debugger.rs`.
- A Newspeak module inline in a test is an `indoc! {"…"}` indented with the Rust around it, the closing `"}` on its own line.
- `vm.rs` holds no dispatch or debugger logic: the `Breakpoint` arm calls one `#[cold]` function in `interpreter/` and acts on its answer.
- Nothing that crosses to the agent's thread (`debugger/remote.rs`) carries a `Symbol`, `Value`, `Root` or handle -- only `String`s, numbers, `Span`s, `ValueId`s and `BreakpointId`s.
- **Compiling never changes**: no body's emitted code, no golden, no `run-corpus` outcome, no image changes. `Breakpoint` has no wire tag; the encoder, `shipped-code` and `disasm` read the decoded view, which answers originals.
- **No check enters the hot path**: the fetch is still one load of a slot; the `Breakpoint` arm is out of line; reports of a frame leaving are made only in the unwinder and in `apply_continuation`'s arms other than `Deliver`'s; a step into's held request is a poll bit. The `codegen` gate's budgets (`xtask/src/codegen.rs`: `vm::run` 9,320 instructions / 54 wide loads, `resume_caller` 300 / 2, `finish` 580 / 2) are not raised.
- A breakpoint is keyed by its body (`Rc<CompiledCode>`) and index, never by code id; a full collection treats every patched body's code id as named.
- **The run is single-threaded and a stop is at the safepoint**: a breakpoint, a step and an exception stop leave their stretch for the run loop's safepoint and stop in `Interpreter::stop`, never inside a leaf or the arm.
- Editing `Kernel.ns` changes the shipped source's fingerprint: `regenerate_the_golden_fixture` (`tests/image.rs`) rewrites `tests/fixtures/golden-image.bin` in the same commit; every new member has a full doc comment (`crates/ns-runtime/tests/core_library_documentation.rs`); `cargo run -p ns-analyzer -- fmt crates/ns-runtime/core-library` after the edit; the file stays LF.
- Every commit runs `cargo xtask gates commit`; also `codegen` for a commit touching `vm.rs`, `interpreter/mod.rs`, `interpreter/sends.rs`, `heap.rs`, `heap/frames.rs` or `bytecode/compact.rs`; `images` for one touching `bytecode.rs`, `bytecode/` or `image/`; `caches` for one touching `interpreter/inline_cache.rs`. The batch ends with `cargo xtask gates end-of-batch` (Task 11); every commit before it is work in progress. Subagents run every command in the foreground.
- Comments explain the decision, not the mechanics. Docs describe the current state; `debugger.md`'s "Planned:" paragraphs that a task builds are rewritten in the present tense by that task.

## Review Focus

1. **A breakpoint at a statement start that is a send in machine code, in a loop**: the stop must come at every iteration, the original send must run exactly once per pass -- never twice after a stop (the past-once token) nor skipped -- with the JIT on, in baseline and in a body an optimized copy had inlined. Pinned in Task 3 (`a_breakpoint_in_compiled_loop_stops_every_iteration_and_sends_once`).
2. **A step over in recursion**: a step over the recursive call must stop in the same activation, never in the deeper one, and a step out of the deeper one must stop in its caller, the shallower activation of the same body. Pinned in Task 4 (`a_step_over_a_recursive_call_stays_in_its_activation`).
3. **A step whose frame leaves by an unwind or a resumed exception**: a step over a statement that raises an error a handler below catches stops in the handler block; a step out of an `ensure:` block the unwinder ran stops at the next place the program reaches. Pinned in Tasks 5 and 8.
4. **Removing a breakpoint while a frame stands at it**: removing it at the stop and continuing must execute the original exactly once; a body freed by an install while patched must not leave its original lost. Pinned in Task 2 (`removing_the_breakpoint_one_stands_at_runs_the_original_once`) and Task 2's install test.
5. **A breakpoint in a shipped quick method** (`True>>ifTrue:`): it stops while set and the fast path returns once it is removed, outcomes unchanged under the JIT. Pinned in Task 3.
