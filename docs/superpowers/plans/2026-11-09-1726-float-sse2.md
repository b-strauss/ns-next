# Float arithmetic in machine code, and x86-64-v2 required — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every `Float` operation that has a machine instruction runs in machine code -- in baseline code through a row stub of its method, in optimized code as a node -- instead of the mirror method leaf, and the binary requires x86-64-v2 on x64.

**Architecture:** One architecture-neutral emitter, `jit/floats.rs`, lowers a `FloatOperation` through new macro-assembler idioms -- decode a `SmallFloat64` or a boxed `Float` (and, where the row accepts one, a `SmallInteger`) into a floating-point register, compute with the new `ns-assembler` operations, tag the result or box it inline in eden -- and declines, before it wrote anything, for every case it does not answer, which the row's leaf then decides as today. The baseline calls it from `RowStub`s, which a method whose fast path is a `Float`, `Integer` or `Number` row now gets; the optimizing tier calls it from a `FloatOperation` node, the arm of a type-case on a `Float` receiver, whose decline goes to the send or traps, as `IntegerBinary`'s does.

**Tech Stack:** Rust 1.98.0; `crates/ns-assembler` (x64, AArch64), `crates/ns-runtime/src/jit/` (`macro_assembler.rs`, `targets.rs`, new `floats.rs`, `optimizing/`), `builtins/primitive.rs`, `heap/machine_words.rs`; `iced-x86` and `yaxpeax-arm` (dev-dependencies, present); `cargo-nextest`, `cargo xtask gates`.

**Spec:** the decisions below, made with the user on 2026-11-09, and `docs/OPEN-WORK.md`'s entry "`Float` arithmetic in SSE2, and the CPU's features asked once", which Task 8 replaces. Background: `docs/design/execution.md`, "Sends in machine code" (the mirror method stub, `MachineCall`), "Planned: the optimizing JIT" -- "Numbers", "Inlining" -- and "Inlining" (the type-case, `expressed`).

## Decisions of 2026-11-09 (with the user)

1. **Baseline: row stubs.** A `Float` row's method -- and the mixed `Integer` and `Number` rows -- runs through a `RowStub` (`MachineCall::Stub`), Cog's compiled primitive (`genFloatArithmetic:preOpCheck:boxed:`), never through code inline at each arithmetic site.
2. **Optimized code: tagged float nodes now.** A type-case arm on a `Float` receiver whose callee is a float row is a `FloatOperation` node -- tagged in and out, no interrupt point on its fast path -- with a fallback send or a trap as `IntegerBinary` has; stage 5 makes its ends conversions to and from raw `Float64`.
3. **A result outside `SmallFloat64`'s range is boxed inline in eden** (Cog's `genInstantiateFloatValue`, Maglev's `Float64ToTagged`); a full eden declines.
4. **All four groups:** binary (`+ - * /`, `< > <= >= =`) with a `Float` receiver; unary with one instruction (`sqrt negated abs isNaN isFinite isInfinite asInteger`, `SmallInteger asFloat`); rounding (`floor ceiling truncated rounded`); mixed, a `SmallInteger` receiver with a `Float` argument (`Integer`'s `+ - * < > <= >= =`, `Number`'s `/`). The libm functions, `hash` and printing stay leaves.
5. **The binary requires x86-64-v2:** built with `target-cpu=x86-64-v2` for every x86_64 target; `ns-next` and `ns-next-analyzer` check it first in `main` and refuse with a message. `roundsd` (SSE4.1) is emitted without a choice.
6. **No extension forms beyond v2.** No CPU detection beyond the start check, no feature selection in the macro assembler, no stress mode for base forms; templates for `Integer`'s bit operations and the BMI2/`lzcnt` question are an `OPEN-WORK.md` item of their own.

- **Exactness:** every stub and node answers bit for bit what the row's leaf answers (`builtins/numbers/float.rs`, `integer.rs`, `tower.rs`), or declines before it wrote anything. In particular: a `SmallInteger` converts to the nearest double, ties to even (`cvtsi2sd`/`scvtf`), for arithmetic, while the orderings and `=` against a `SmallInteger` are exact for every `SmallInteger`, as `tower::float_order` is (Cog's sequence, below); an ordering with a NaN answers `false`; `=` answers `true` for two NaNs, which the stub leaves to the leaf by declining when two `Float`s compare unordered; `/` by zero is IEEE's; `floor`, `ceiling`, `truncated` and `rounded` answer a `Float`, `rounded` half away from zero; `negated` flips the sign bit; `asInteger` answers a `SmallInteger` or declines.
- **Encoding of `SmallFloat64`** is `heap/value.rs`'s: decode `shr 3; if > 1 then add 896 << 53; ror 1`; encode `rol 1; if > 1 then sub 896 << 53; shl 3; or 4`, after the range test `is_small_float_bits` states; the macro assembler takes `896 << 53`, the tag and the tag bits from `Heap::machine_layout()`, never a literal.
- **Floating-point registers:** templates and nodes use only `Roles::float_scratch`, three registers every convention has the callee *not* preserve (`xmm0`–`xmm2`, `d0`–`d2`), so the entry stub saves none; no floating-point value lives across a leaf call, an exit or a node boundary.
- No file under `jit/` but `macro_assembler.rs` names an architecture's register or encoder outside a test module (`tests/jit_architecture_split.rs`).
- Every new encoding constant of `ns-assembler` is a named `const` with its source (Intel SDM Vol. 2 section, developer.arm.com instruction page); no other integer literal than 0 and 1 (`tests/encoding_sources.rs`).
- Names are written out. `ns-runtime` forbids `unsafe`. No new external dependency.
- A new golden's `.toml` is recorded with `NS_NEXT_NO_JIT=1` and its output established as right by reading the program.
- Every member of a shipped core-library module keeps its doc comment; this plan changes no `.ns` of the core library.

## Review Focus

1. **Signed zero.** `-0.0` is the word `(1 << 3) | 4`; `0.0 negated`, `-0.4 rounded`, `-0.5 ceiling`, `-0.0 floor`, `0.0 - 0.0`, `-0.0 * 1` and `0.0 = -0.0` must answer what the leaf answers. Test: Task 4's and Task 5's goldens `float_signed_zero.ns`.
2. **The range's edges.** The smallest and largest `SmallFloat64`, the doubles just outside (exponent 896 with a zero mantissa, which must box, and 1152), subnormals, `inf` and NaN as results and as boxed operands of every operation. Test: Task 4's golden `float_range_edges.ns`.
3. **Mixed operands at 2^53.** `(2 raisedTo: 53) + 1` against `(2 raisedTo: 53) asFloat` in `<`, `<=`, `>`, `>=` and `=` (exact, in machine code: not equal, and greater) and in `+` (rounded); `(2 raisedTo: 59) + 1` likewise; a `SmallInteger` near the 61-bit bound converted; each with the `SmallInteger` as receiver and as argument. Test: Task 6's golden `mixed_float_integer.ns`.
4. **A full eden while boxing.** The inline box's slow path declines and the leaf allocates; under `NS_NEXT_STRESS_SCAVENGE` and `NS_NEXT_STRESS_COLLECT` every boxed result survives. Test: Task 4's `a_float_boxed_with_eden_full_is_the_leaf_s` and the stress gate.
5. **No callee-saved floating-point register.** `float_scratch` under each `Abi` is volatile, or Win64's `xmm6`–`xmm15` and AAPCS64's `d8`–`d15` would be clobbered behind the host's back. Test: Task 3's `float_scratch_registers_are_volatile_under_every_convention`.

### Task 7: Float nodes in optimized code

**Files:**
- Modify: `jit/optimizing/plan.rs` (`expressed`), `build.rs` (`Expressed::Float`, `expressed_primitive`), `graph.rs` (`Node::FloatOperation`), `emit.rs`, `liveness.rs`/`allocate.rs`/`metadata.rs` wherever `Node::IntegerBinary` is matched exhaustively

**Interfaces:**
- Consumes: `FloatOperation::of_primitive`, `floats::emit` (Task 3).
- Produces: `Node::FloatOperation { operation: FloatOperation, program_counter: u32, destination_register: u16, value: ValueId, receiver: ValueId, argument: Option<ValueId>, fallback: Option<BlockId> }` -- a simple node, no interrupt point; its decline goes to `fallback` (the arm's send through its cell, whose stub then decides) or, with `None`, to a trap, by `IntegerBinary`'s rule (`fallback: None` where the site never trapped).
