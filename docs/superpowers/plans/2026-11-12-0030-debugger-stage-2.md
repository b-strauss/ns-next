# Debugger Stage 2: the Metadata — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stopped frame shows its name, the statement and the send it stands at as spans of its module's current text, and its named variables -- a block's over its whole lexical chain -- from stop locations and variable tables both lowerings collect when the debugger compiles the body's declaration again on demand and finds it equal to the running body.

**Architecture:** Both lowerers take an optional `MetadataCollector` and record, per body, its statement starts (inlined blocks' included), its sends with their receiver and selector spans, and its variables with the place each is read from in that body's frame. The debugger finds a running body's declaration from its frame (mixin, side, member), parses and resolves its module's current text (a shipped module's resolution the boot made), compiles that one mixin level again with the collector, pairs the running bodies with the recompiled ones by code equality that ignores spans, and caches the tables per body on the `Mutator`. Stage 1's stack trace and variables read the tables; the pause stress mode reads them at every stop; an oracle compiles every golden's bodies again under both lowerings, and through `build`/`load`.

**Tech Stack:** Rust 1.98.0 (edition 2021), `cargo-nextest`, `libtest-mimic` (already a dev-dependency of `ns-cli`); no new dependency.

**Spec:** `docs/design/debugger.md` -- decisions 4, 5 and 10 to 15; "Compiling the metadata again"; "Reading the stack at a stop" (the planned paragraph); "The pause stress mode"; "Planned: the order of building it", stage 2.

## Global Constraints

- `ns-runtime` and `ns-syntax` forbid `unsafe`; no new external dependency.
- Names are written out (`CLAUDE.md`, Conventions): no identifier of one or two characters, no truncated word.
- Never `{:?}` a `Value`, never `.unwrap()`/`.expect()`/`{:?}` an `EvaluationResult`; tests use a local `expect_ok` copied from a neighbour (`crates/ns-runtime/tests/stress.rs`).
- A Newspeak module inline in a test is an `indoc! {"…"}` indented with the Rust around it, the closing `"}` on its own line.
- Object, frame and activation access goes through `crates/ns-runtime/src/heap.rs`; a missing accessor is added there.
- Nothing that crosses to the agent's thread (`debugger/remote.rs`) carries a `Symbol`, `Value`, `Root` or handle: only `String`s, numbers, `Span`s and `ValueId`s.
- **Compiling never changes for a program**: with no collector every lowering emits exactly what it emits today (the goldens, `run-corpus`, the embedded shipped code's fingerprint and `tests/fixtures/golden-image.bin` stay as they are). The collector only observes.
- **The recompilation registers nothing and runs nothing**: no `Heap::mixin_id`, no `code_id`, no application, no Newspeak code; a shipped module is compiled from `resolved_kernel()` / `resolved_shipped_module(name)`, never through a new caller of `resolver::resolve_kernel`; a program module through `resolver::resolve`. Its result is compared and its tables kept, never installed.
- **An image is untrusted input**: a crafted text that does not parse, does not resolve, or does not hold the declaration answers "no metadata", never a panic.
- Every commit runs `cargo xtask gates commit`; a commit touching `interpreter/mod.rs` or `heap.rs` also `cargo xtask gates codegen`; a commit touching `crates/ns-runtime/src/image/` or `golden_round_trips.rs` also `cargo xtask gates images`. The batch ends with `cargo xtask gates end-of-batch`; a commit before that is work in progress. Subagents run every command in the foreground.
- Comments explain the decision, not the mechanics. Docs describe the current state.

## Review Focus

1. **A block whose creator returned without keeping its registers**: a variable the block did not capture lives nowhere; it must show as not available -- never `nil` from a field, never a read of a dead register (a debug build refuses the poison word) -- pinned in Task 5 (`an_uncaptured_variable_of_a_returned_creator_is_not_available`).
2. **An edit elsewhere in the module**: a body after the edited declaration keeps its metadata, its spans moved to the current text; the cache must not answer the spans of the text before the install -- pinned in Task 4 (`an_install_moves_the_spans_of_an_unedited_body`).
3. **A superseded version the edit changed, still on the stack**: no metadata, the frame shows stage 1's `argument N` / `register K`, no panic -- pinned in Task 5.
4. **Constructs whose bodies are built off the plain path**: a kernel `Closure` method with an unwind marker (its code is cloned), a lazy slot's getter, a simultaneous slot's future block, a `<:` clause, a class-side method, a body-less declaration's initializer -- each must compile again equal; pinned by Task 4's tests and Task 6's oracle over every golden and every shipped body.
5. **An image without source or with crafted text**: `--strip-source` and a text whose declaration path does not exist answer no metadata, never a panic -- pinned in Task 4 (`a_crafted_text_without_the_declaration_gives_no_metadata`) and Task 5.

pub(crate) struct BodyMetadata {
    /// Every statement start in emission order: the body's own statements,
    /// its local, slot and simultaneous initializers and prologue entries
    /// (wherever `statement_program_counter` gets a range), and every
    /// statement of an inlined block.
    pub(crate) statements: Box<[StatementEntry]>,
    /// Every send, `SendMirror` included, by ascending index.
    pub(crate) sends: Box<[SendEntry]>,
    /// The body's own variables first (parameters, then temporaries, in
    /// resolver order), then each enclosing scope's, outward.
    pub(crate) variables: Box<[VariableEntry]>,
}
pub(crate) struct StatementEntry { pub(crate) instructions: Range<u32>, pub(crate) span: Span }
pub(crate) struct SendEntry {
    pub(crate) index: u32,
    pub(crate) call_site: Option<CallSite>, // None for a SendMirror
    pub(crate) receiver: Option<Span>,      // None for an implicit unary send kept as an Identifier, and a setter
    pub(crate) selector: Box<[Span]>,       // MessageSend::selector_spans; an Identifier's span for an identifier send or setter
}
pub(crate) struct VariableEntry { pub(crate) name: Symbol, pub(crate) depth: u16, pub(crate) place: VariablePlace }
pub(crate) enum VariablePlace {
    Register(u16),                         // in this frame: a parameter, temporary or copied value
    Outer { hops: u16, register: u16 },    // `hops` closures' captured frames out
    Vector { vector: VectorHolder, slot: u16 },
}
pub(crate) enum VectorHolder { Register(u16), Outer { hops: u16, register: u16 } }

pub(crate) struct MetadataCollector { /* RefCell<HashMap<usize, BodyMetadata>> keyed by EncodedBody::identity */ }
impl MetadataCollector {
    pub(crate) fn new() -> MetadataCollector;
    pub(crate) fn record(&self, code: &CompiledCode, metadata: BodyMetadata);
    /// Moves the entry of `from` to `to`: a body cloned after it was compiled (the kernel's unwind marker).
    pub(crate) fn rekey(&self, from: &CompiledCode, to: &CompiledCode);
    pub(crate) fn take(&self, code: &CompiledCode) -> Option<BodyMetadata>;
}
```

- Produces, in `bytecode/compact.rs`: `pub(crate) fn identity(&self) -> usize` on `EncodedBody`, the address of its `slots` allocation: a body has at least one instruction, and moving the `CompiledCode` into its `Rc` does not move the allocation, so the address names the body for as long as it lives.
- A `VariableEntry` carries no instruction range: an inlined block declares no parameter and no temporary (`control_flow.rs:54-63`), so every variable a body names is in scope over the whole body, `nil` from its start (decision 13).
- `depth` is the lexical distance in frame scopes (inlined scopes do not count, as `hops_above`, l.252-260, counts): 0 for the body's own variables.

pub(crate) fn frame_registers_kept(&self, frame: FrameReference<'gc>) -> bool;
```

A frame's `BodyOrigin`: a method's mixin is its current class's application's (`Heap::class_application`), its member the method's selector (`Heap::code_method`); an initializer's `Heap::initializer_mixin(class, body)`; a clause's and a factory's their class's mixin; a block's the origin of the root of its family -- the body of its current class's mixin level whose `created_blocks()`, walked transitively, hold it. With metadata, the variables are `self` then each entry at most one per name (the innermost), read by its place: `Register` from the frame; `Outer` by `hops` steps of the closure's captured frame (`Heap::activation_captured`, `frame_captured`), `None` when a frame on the way has no registers kept; a `Vector` through its holder, then the element. Without metadata the variables are stage 1's.
