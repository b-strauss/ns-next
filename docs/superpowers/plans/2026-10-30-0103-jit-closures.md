# Closures, non-local return, allocation and the barrier in machine code Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Road step 8's fourth stage on x64. Afterwards a compiled body
exits only at an error, at a poll that found a request, at a
continuation other than `Deliver`, and at an unwind it cannot cut. To
get there, machine code itself allocates, stores through the barrier,
makes closures, calls them, and cuts non-local returns.

**Architecture:** The work comes in three parts, each measured against
the tree before it.

- **4a.** Eden's cursor moves where machine code reaches it, with an
  inline bump whose cold path is a leaf, and the barrier goes inline with
  its four early outs. On top of those come the slots, the vectors,
  `at:put:`, the setters, `AllocateInstance` and the initializers'
  invocations.
- **4b.** `MakeClosure` reifies its frame and allocates the closure
  inline. A closure's activation becomes a compiled call through a stub.
  The outer locals and the futures follow.
- **4c.** A routine of its own cuts a non-local return whose home lies in
  the current stretch. Any other non-local return exits to the one
  unwinder.

- **4d.** Everything that grows is reclaimed (decided with the user on
  2026-10-30): the code zone is compacted as Cog compacts it; the exit
  budget decays and abandonment is reversible; program-made symbols die
  with their objects; every side table requests a full collection past
  its growth limit; site ranges slide at a full collection; committed
  memory is given back with hysteresis.

**Tech Stack:** Rust 1.98.0, edition 2021; no new dependency.

**Spec:** `docs/design/execution.md`, "Stage 4: closures, non-local
return, allocation and the barrier" (the six decisions there were taken
with the user on 2026-10-30). Read it with "Planned: the deoptimization
contract" ("Returns", "Non-local return and unwinding"), "The closure
keeps its defining activation", "Unwinding", and `docs/design/memory.md`,
"Generations" and "What the collector traces".

## Global Constraints

- **Earlier plans.** Everything in the Global Constraints of
  `docs/superpowers/plans/2026-10-28-1928-jit-sends.md` still holds:
  - `unsafe` appears only in `ns-memory`;
  - names are written out;
  - machine code holds no handle;
  - code is written only through `CodeWriter`;
  - the JIT is compiled in only where `cfg(ns_jit)`, and
    `NS_NEXT_NO_JIT=1` turns it off;
  - `vm.rs` holds no dispatch logic;
  - a cell is written only from its entry;
  - a stub does what `Mutator::act_with_base` does for its target and
    nothing more.
- **Templates and leaves** (CLAUDE.md, "Machine code is a lowering of the
  interpreter's instructions"):
  - A template stores into the frame only after its last decline or exit.
  - A leaf runs no Newspeak code, cannot collect, reads no other
    activation and never pushes.
  - A leaf answers "re-execute" only before it changed anything but a
    send's argument slots.
  - The cut (Task 14) is the one routine that reads and pops other
    activations. Its own rule goes into CLAUDE.md in that task.
- **Machine words.** No word that machine code reads or writes between
  two leaf calls lies in the `Mutator`. Eden's cursor gets an allocation
  of its own in `ns-memory`. New per-application words go in the
  application id table's reservation. New lasting addresses go in the
  entry block's free words 22-28. A lasting word is written only where
  what it names changes, which marks the block stale.
- **The barrier** (CLAUDE.md, "Every store into an existing object goes
  through `heap.rs`'s store accessors and their write barrier"):
  - Every store machine code makes into an object it did not allocate in
    the same template takes the inline barrier.
  - An old allocation is born remembered, so the leaf's old path keeps
    `remember`.
  - `AlignedBytes` data begin at the block's first 32-byte address. An
    inline byte access computes that offset as `heap/object.rs` does.
- **Registers.** No file under `jit/` other than `macro_assembler.rs`
  names a register. A new need is a new named role in `Roles`, held by
  `crates/ns-runtime/tests/jit_architecture_split.rs`.
- **Analysis hooks.** Every new instruction effect, of which none is
  planned, would be declared in `bytecode.rs`'s exhaustive matches.
  `outer_reach_of` is untouched.
- **Goldens.** The goldens' outcomes do not change. A new golden's

## Review Focus

1. **A young value stored by machine code into an old object** (an
   object tenured before a loop whose compiled body stores freshly
   allocated objects into it) must be remembered. Otherwise the next
   scavenge reclaims what the old object names. Pinned by Task 3's
   `an_inline_store_of_a_young_value_into_an_old_object_remembers_it`,
   with `NS_NEXT_STRESS_SCAVENGE`'s verification of the remembered set
   over every golden.
2. **A compiled loop that allocates past the scavenge threshold and past
   eden's end with no poll between**, which is straight-line code
   allocating more than 512 KiB. It must request the scavenge, carry on
   up to the ceiling, then allocate old and born remembered, exactly as
   the interpreter does. Pinned by Task 2's
   `machine_code_allocates_past_eden_as_the_interpreter_does`.
3. **A `^` from a block whose home has returned**, or whose home lies
   below an `ensure:` activation, run from compiled frames. The first
   must raise `cannotReturn:`. The second must run the `ensure:` block
   exactly once, in the interpreter's order. Pinned by Task 14's goldens
   `non_local_return_through_ensure.ns` and
   `non_local_return_dead_home.ns`.
4. **A block's activation observed by reflection after machine code made
   and ran it.** Its `enclosingActivation`, the dead creator's program
   counter and its `uncontinuable` flag must read as under
   `NS_NEXT_NO_JIT`. Pinned by Task 9's golden
   `goldens/runtime/jit/reified_frames.ns`.
5. **A recursion through compiled closure calls overflowing the depth
   limit**, both a block that calls itself through a slot and one that
   an inlined `ifTrue:` of the reference lowering runs. It must raise at
   the activation the interpreter raises at, exemption included. Pinned
   by Task 10's golden `goldens/runtime/jit/closure_recursion_overflow.ns`.

6. **A cell, machine entry row or `returns` key naming a moved body's
   old address** calls into the middle of other code, or into freed
   bytes, at exit status 0. Pinned by:
   - Task 18's `a_compaction_moves_a_body_its_cells_call` and
     `a_moved_block_body_is_called_through_its_row`;
   - `NS_NEXT_STRESS_ZONE=1` over every golden, which frees and moves
     at the safepoints its schedule picks.
7. **A body that is not position-independent**: an absolute address or
   a `rip`-relative reference to anything outside its own bytes would be
   wrong after a slide. Pinned by Task 18's
   `a_body_assembled_at_two_offsets_is_the_same_bytes`, run over a body
   of every template family (sends, closures, allocation, the cut), and
   by `a_moved_body_keeps_its_closure_sites`, which also catches a slide
   that breaks a body's alignment.
8. **A compaction with a return address into the zone on the native
   stack.** Pinned by the debug assertion on
   `JitState.entries_in_progress` in `Mutator::compact_code_zone`, and
   by the zone stress mode with `NS_NEXT_STRESS_EXIT=1`.
9. **Two Symbol objects of one text**, after a program-made symbol meets
   a later literal, an edit's selector or an image's symbol. `==`
   breaks, and `perform:` answers `doesNotUnderstand:` for a method that
   exists. Pinned by Task 21's
   `a_program_made_symbol_finds_a_method_installed_after_it`,
   `goldens/runtime/symbols/program_symbol_identity.ns` and
   `an_image_keeps_a_program_made_symbol`.
10. **A feedback base left unrewritten by a slide** (a closure, a
    suspended frame, a continuation, a cache `Target`). Its sends then
    hit another family's sites and act on them. Pinned by Task 22's
    `a_closure_made_before_a_slide_hits_at_its_moved_range` and
    `a_suspended_frame_resumes_at_its_moved_range`, and by
    `NS_NEXT_STRESS_COLLECT=1` sliding at every collection with a hole.
11. **Machine code entered at a base it was not compiled for** after a
    slide. Pinned by `machine_code_of_a_moved_family_compiles_again` and
    by the base check `interpreter_entry` already makes
    (`jit/mod.rs:1461-1475`).
12. **Revival that oscillates**: a body that always exits recompiling at
    every scavenge and filling the zone. Pinned by Task 20's
    `a_body_that_always_exits_compiles_at_most_once_per_two_scavenges`.
13. **A decommit below a live word**: the stack's top or a frame's
    window end, a live site's cell, a row under the bound machine code
    reads. Pinned by Task 23's
    `a_machine_entry_row_past_the_lowered_bound_reads_as_none`,
    `a_deep_recursion_gives_its_stack_pages_back` (whose second
    recursion runs over recommitted pages), and the seat sentinel's
    test.
14. **A table limit that fires on ordinary programs**, which would show
    as a slowdown from extra full collections. Pinned by Task 17's
    `no_golden_reaches_a_table_limit` and Task 24's record of
    `table_collections == 0` over every benchmark.

### Task 2: Eden's cursor where machine code reaches it, and the bump

**Files:**
- Modify: `crates/ns-memory/src/lib.rs` (`BumpCursor` and its users).
- Modify: `crates/ns-runtime/src/heap/space.rs`, `heap.rs`
  (`allocate_block`).
- Modify: `jit/macro_assembler.rs`, `jit/leaves.rs`, `jit/stubs.rs`
  (`BlockWord::EdenCursor = 22`).
- Test: `crates/ns-memory` unit tests, `crates/ns-runtime/tests/jit.rs`.

**Interfaces:**
- Produces:
  - `ns_memory::SharedCursor`: an allocation of two `Cell<usize>` words,
    top then limit, behind an `Rc` (the machine words' pattern).
    `Reservation` reads and writes its cursor only through it, so
    `bump`, `bump_array`, `bump_up_to`, `set_bump` and `record` keep
    their contracts.
  - `Reservation::bump_cursor_address() -> usize`: the address of the
    top word, the limit word 8 bytes past it.
  - In the entry block, `BlockWord::EdenCursor` holds that address. It
    is lasting, written when the block is made and when the space's
    reservation is replaced, which marks the block stale.
  - The idiom `MacroAssembler::bump_allocate(object: Register, bytes: i32
    or a register, header: u64 word or register, class_word: Register,
    slow: Label)`. It loads top and limit, takes `slow` when
    `limit - top < bytes`, stores the new top, and writes the header word
    and the class word. `object` answers the object's byte offset, which
    is the object's word, as `Value::object` makes it.
  - `Leaf::Allocate` (arguments: the word count and the header and class
    words). It calls `Heap::allocate_block`'s cold decision: request the
    scavenge, bump to the ceiling, or allocate old and remember. It never
    collects and answers the offset. The template's slow path calls it
    and rejoins the fast path's fill.
  - `ns_assembler`: a 32-bit `test_immediate` (`Width::Word32`), so the
    remembered bit 31 tests without sign extension, and
    `shift_right_logical`. Each encoding constant is named and sourced,
    and each encoding is checked against `iced-x86`.

### Task 3: The barrier, the vectors and `MakeArray`

**Files:** `jit/macro_assembler.rs`, `jit/leaves.rs` (`Leaf::Remember`),
`jit/allocation.rs`, `jit/baseline.rs` (the arms `MakeArray`,
`LoadVector`, `StoreVector`), `heap.rs` (`machine_layout` gains
`nursery_end`, `remembered_bit` and the nil word).

**Interfaces:**
- Produces:
  - `MacroAssembler::store_with_barrier(holder: Register, displacement:
    i32, value: Register, scratch: Register)`. It stores the word, then
    applies the early outs in Cog's order:
    1. `value` immediate or nil, which is the tag test plus a compare with
       0;
    2. holder young, `holder < NURSERY_END`;
    3. value old, `value >= NURSERY_END`;
    4. header bit 31 set.

    checks: an `IndexablePointers` object, with the index inside it. On a
    mismatch they exit `Reexecute` before any store, so the interpreter
    raises.

### Task 5: The own-slot instructions

**Files:** `heap/application_ids.rs` (a row gains its slot base and its
flags), `jit/allocation.rs`, `jit/leaves.rs` (`Leaf::OwnSlots`),
`jit/sends.rs` (the prologue), `jit/materialize.rs`, `jit/baseline.rs`
(the arms `LoadOwnSlot`, `InitializeSlot`, `InitializeSlotProvisionally`,
`ReturnSlotIfFilled`).

**Interfaces:**
- Produces:
  - **The application id table's row.** It grows from one word to four:
    1. the dispatch id;
    2. the instance header (Task 6);
    3. the slot base;
    4. the flags.

    Flags bit 0 means its slots take §3.1.1's value check
    (`check_value_slot`). The rows are written wherever the row's
    dispatch id is written today.
  - **The frame's guard and entered level.** For code that addresses its
    own slots, the prologue stores the guard "none" and the entered
    level (the current class's application, as the push records it)
    into their header places. `materialize` then writes neither for such
    code.
  - **The own-slot templates.** Each compares the receiver's guard with
    the frame's guard word. On a mismatch it calls `Leaf::OwnSlots`,
    which runs `check_own_slots`'s cold check
    (`interpreter/locals.rs:156-167`), records the guard in the frame and
    answers 0, or EXIT for a receiver without the level. The template
    then exits `Reexecute`.
    - The slot base is read from the entered level's row.
    - `InitializeSlot` with a value check, or with a future value, calls
      `Leaf::Step`, which keeps the interpreter's error and future paths.
      Otherwise it stores with the barrier.
    - `ReturnSlotIfFilled` returns as `return_from` does when the field
      is not the unfilled sentinel.

### Task 6: Instantiation and the initializers' invocations

**Files:** `heap/application_ids.rs` (the instance header word),
`heap/object.rs` (the class object's builtin field displacement in
`machine_layout`), `jit/allocation.rs`, `jit/leaves.rs`
(`Leaf::Initializer`), `jit/sends.rs`, `jit/baseline.rs` (the arms
`AllocateInstance`, `InitializeInstance`, `InitializeSuperclass`,
`InitializeAppliedLevel`, `CheckAppliedClause`, `LoadEnclosingObject`).

**Interfaces:**
- Produces:
  - **The instance header word.** A row's instance header word is the
    application's `InstanceHeader` as a header word, or 0 where
    `allocate_for_factory` does anything but `allocate_instance_with`:
    every builtin arm, a refusal, a value refusal, an ephemeron, or a
    count needing an overflow word.
  - **`AllocateInstance`.** The receiver must be a class object, checked
    by its format, and its builtin field must be nil (read afresh at
    every instantiation, as the cache rule asks). The row's word must be
    non-zero. Then it bump-allocates and nil-fills. Anything else calls
    `Leaf::Step`, which runs `allocate_instance`, and a refusal there
    exits so the interpreter raises.
  - **`Leaf::Initializer`** (arguments: the frame, the program counter).
    It decides the body an `Initialize*` instruction pushes as
    `vm.rs`'s arm does. It writes `CalleeReceiver`/`CalleeClass`, counts
    the entry with `note_entry`, and answers the callee's machine entry
    address, or EXIT when the callee has none or the check fails. The
    template places the arguments, calls the entry as a send does, and
    stores the answer into `destination`.
  - **`CheckAppliedClause`** calls `Leaf::Step`.
  - **`LoadEnclosingObject`** is a template over the existing
    `load_enclosing_object` idiom.

## Part 4d: everything that grows is reclaimed

The user's requirement (2026-10-30): a server running for days must not
grow without bound. Six decisions were taken with the user that day,
which Task 16 writes into the design documents with the inventory and
the prior art behind them: the code zone compacted as Cog compacts it;
the exit budget decaying and abandonment reversible; program-made
symbols dying with their objects; side tables requesting a full
collection past a growth limit, with no time-based watchdog; site ranges
sliding at a full collection; committed memory given back with
hysteresis. Each task below names the decision it builds.

### Risks (read before the tasks)

1. **Decision 3 cannot be built as worded without `unsafe` in
   `ns-runtime`, so Task 21 builds it another way.** The decision says
   "a full collection frees the number and the text, and the number is
   reused". Three facts stand against that:
   - `Symbol::as_str` answers a `&'static str` that `Symbol::intern`
     made with `Box::leak` (`symbol.rs:115-127`). Freeing that text
     takes `Box::from_raw`, which `ns-runtime` forbids. Freeing it
     safely means changing `as_str`'s contract at every caller, and
     about 250 `.as_str()` calls lie across 120 files.
   - The interner is one per thread (`symbol.rs:97-99`), shared by every
     interpreter on the thread. One heap's collection cannot know
     whether another heap still holds a number.
   - A `Symbol` is a `Copy` `u32`, held by compiled code, cache keys,
     `ReturnSite.selector`, frame headers and every Rust table. A
     recycled number would need a scrub of all of them.

   Task 21 therefore never gives a program-made symbol a
   number. A `Symbol` object already holds its own text
   (`Heap::allocate_symbol` is `allocate_string`, `heap.rs:2829-2835`),
   so a program-made symbol whose text nothing has interned is just
   that object. It is recorded in a per-heap weak table keyed by its
   text, and it dies with the object. The interner stays append-only
   and permanent, bounded by the source compiled and the images loaded.
   This is the decision's outcome (collectable, bounded, nothing
   reachable after death) by another mechanism: no number exists to
   recycle. **The user confirmed this mechanism on 2026-10-30**, as the
   faster of the two: sends, caches and machine code see only permanent
   numbers, where reference counts would cost on cache fills, installs
   and text reads. The literal alternative needs per-heap reference counts in
   the interner, a non-`'static` text API at every caller, and a scrub
   of the global cache's keys. It is sketched at the end of Task 21.
2. **Site-range compaction invalidates machine code.** A body's
   compiled sends address their cells at `index × CELL_BYTES`, computed
   from the body's feedback base at compile time (`jit/sends.rs:950-958`).
   A closure template moves the base in as an immediate
   (`jit/closures.rs:501, 553-557`). So every body whose family's range
   moves loses its machine code (Task 22) and compiles again on demand.
   That is sound but costs a recompile per moved family. The
   compaction's threshold (a quarter of the table free) keeps it rare.
   Addressing cells from a base register instead would be a hot-path
   change, and this plan does not propose it.
3. **Decision 6's list leaves out the code zone.** Task 23 decommits the
   zone above its high mark too, by the same rule. The user agreed to
   the addition on 2026-10-30.
4. **Decision 1 says "code whose code row a full collection frees".** A
   code row is freed when nothing names the code id
   (`heap/reclaim.rs:553`), and a live method's body often has no id.
   Freeing machine code there would discard hot code at every
   collection. Task 19 frees the code of a body that **died**, which is
   what `execution.md` means by "Code dies with its mixin's row": the
   body's mixin row was freed or superseded, and
   `InstalledBody.code` (`jit/mod.rs:502-512`) no longer upgrades.

    `cogitX64SysV.c:5723-5744`):
    1. **Mark the active bodies.** Every activation on the stack and
       every suspension row has its body's usage set to `MAXIMUM_USAGE`
       (`markActiveMethodsAndReferents`, `cointerp.c:17709-17725`).
    2. **Free what is always freed.** A body is marked free when any of
       these holds:
       - its `code` no longer upgrades;
       - its slot does not name it (state not `COMPILED`, another zone,
         or `map` not its index), which covers abandoned, recompiled and
         superseded bodies.
    3. **Free by usage.** Sweep `freeable` from 0 up to
       `MAXIMUM_USAGE - 1`, marking free every body whose usage is at
       most `freeable`, until the free bytes (the gap at the end plus
       the bodies marked free) reach `zone.limit / 4`
       (`freeOlderMethodsForCompaction`, `cogitX64SysV.c:12897-12925`).
       For each body freed here, `JitSlot::forget` puts it back to
       counting.
    4. **Plan** (`jit::zone::CompactionPlan`): the survivors in ascending
       order, each at `align_up(cursor, alignment)`, from the end of the
       stubs (the first body's start). This yields an old-start to
       new-start table (`planCompaction`, `:13098-13113`).
    5. **Remap every address outside the bodies** through
       `CompactionPlan::remap(address) -> u64`. An address inside a
       survivor moves by its delta. An address of a freed body's entry
       becomes the miss stub's, which `cell_entry` answers for a
       counting body. A stub's address stays.

         the polymorphic blocks' and the global rows' cells.
       - `Heap::remap_machine_entries(&plan)` covers every committed
         row; a freed body's row becomes 0.

       This comes before the bytes move, as Cog updates the stack zone
       and relocates before it copies (`:13400-13417`;
       `cointerp.c:21546-21596`).

       buffer, in ascending order (`compactCompiledCode`,
       `cogitX64SysV.c:12740-12825`).

       - `bodies` rebuilt from the survivors;
       - each survivor's `JitSlot` gets its new `offset`,
         `first_instruction` and `map`;
       - `returns` is rebuilt by shifting each surviving key by its
         body's delta and renumbering `ReturnSite.body`, so that a freed
         body's returns go;
       - `Zone.next_offset` becomes the end of the last survivor.
    8. **Halve** every survivor's usage (`:12756-12757`, `:12806-12807`).
    9. **Clear** `compaction_requested`. Clear `zone_exhausted` when a
       quarter is free. Otherwise keep it until Task 19's next full
       collection, so that a full zone of active code does not compact
       at every safepoint.

    The entry block's lasting words name only stubs, which never move,
    so the block is not marked stale. The debug check at every entry

  compaction at `:10771-10790`, `traced_size` at `:10409`);
- `interpreter/mod.rs` (`new_symbol` at `:2653`, a new
  `program_symbol`);
- `builtins/text.rs:531`;
- every call site of `symbol_value` (33, in `builtins/`,
  `interpreter/edit.rs`, `interpreter/unwind.rs` and
  `image/encode.rs:1851-1860`);
- the `Symbol::intern` calls whose text a program chooses (below);
- `image/decode.rs` (adoption);
- `docs/design/memory.md`, `docs/design/object-model.md` ("Values and
  objects").

**Decisions and why:**
- **Telling program-made symbols from permanent ones.** A symbol is
  permanent when its text was interned: by the compiler, the resolver,
  the image decoder (`image/symbols.rs:111-117`) or the runtime's own
  constants (`symbol.rs:47-64`). Every `Symbol` value in Rust is one of
  these.
  - A program-made symbol is a `Symbol` object whose text nothing has
    interned. It has no number at all, so no number can be recycled,
    and compiled code, a cache key, `ReturnSite.selector`
    (`jit/mod.rs:477-488`), a frame header (`frames.rs:98-139`) and an
    image record can never hold one. The interner is untouched by a
    program: it stays append-only and per thread, and nothing is
    shared across heaps.
  - When a text is interned after a program made a symbol of it, the
    object is adopted (below), so the text then has one object and one
    number.
- **Where the weak hold lives.** In the heap, per heap, as
  `canonical_symbols` (`heap.rs:2102`) is:
  `heap::symbols::ProgramSymbols<'gc>` holds
  `by_hash: IdentityMap<u64, Vec<ObjectReference<'gc>>>`, keyed by
  `Heap::string_hash` of the text and compared by text, so it keeps no
  copy of the text. It also holds `members: IdentityMap<u64, u64>`,
  object offset to hash, the inverse that `symbol_of`'s twin needs. The
  table is weak:
  - pruned with `prune_canonical_symbols`;
  - forwarded by the scavenge's weak pass beside
    `forward_weak_symbols`;
  - rebuilt after every compaction and move as `symbol_of` is;
  - counted in `traced_size`.

  It holds handles, so it follows "A handle means nothing against a
  `Heap` that did not mint it": it lives in the `Heap`, and the brand
  is checked as for `canonical_symbols`.
- **Making one: `Mutator::program_symbol(text) -> Value`.**
  - When `Symbol::lookup(text)` (new: probe, no insert) finds a number,
    it answers `new_symbol(number)`.
  - Otherwise it answers the table's object for the text, or
    allocates one (`allocate_string` with the `Symbol` class, the
    representation `allocate_symbol` already uses) and records it.
  - Past Task 17's limit it requests a collection.
- **Adoption: one text, one object.** Before `new_symbol(number)`
  (`interpreter/mod.rs:2653-2661`) allocates, it looks the number's
  text up in `ProgramSymbols`. If an object is found, it moves that

    the object is in `symbol_of` or in `ProgramSymbols`".

    "not found": `builtins/reflection.rs:684`, `:1455`,

    selector is a program's string.

    are permanent and bounded by the source.

  The task's first step classifies every call site in a table in the
  commit message.
- **The image format.** The wire carries no symbol number: the encoder
  writes a symbol's text into the symbol table
  (`image/symbols.rs:21-57`, `image/encode.rs:1858-1859`), and
  `OBJECT_SYMBOL` keeps its meaning. **No tag is added, renumbered or
  retired**, and `tests/opcode_tags.rs` is untouched. The decoder
  interns every text of the table (`image/symbols.rs:111-117`), so a
  symbol an image carries is permanent, bounded by the images loaded.
  That limit goes into `OPEN-WORK.md` ("A program-made symbol an image
  carries becomes permanent at load"); making it weak there would need
  the decoder's first pass to tell object texts from code texts.
- **The literal alternative, for the record**, is refcounted numbers:
  - a per-entry count in the thread's interner, raised by each heap's

  - a free list of numbers;
  - texts held as `Rc<str>`, with `as_str` replaced by a non-`'static`

- Produces:
  - **`InlineCaches.loose_ranges: BTreeMap<u32, u32>`**, start to size.
    A decoded closure's range is recorded here at its first activation.
    `forget_families` frees a loose range whose base no marked closure
    and no activation names, as it frees a family's.
  - **`InlineCaches::plan_slide(&self) -> Option<SiteSlide>`**, run by
    `reclaim_ids` after `forget_families`. It answers `None` unless the

    debug build's `NS_NEXT_STRESS_COLLECT` slides whenever any range is
    free, so the stress gate exercises every slide.

      ascending order, each with its new start, packed from 0.
    - **`SiteSlide::remap(base: u32) -> u32`** is a binary search.
      `NOT_ASSIGNED` and 0 (a body without sends) stay.
  - **Applying a slide**, in this order, all inside `World::collect`
    between `reclaim_ids` and the end of the compaction:
    1. Move each range's `CacheEntry`s and their cells down in
       ascending order. Polymorphic blocks are named by block number and
       stay. Truncate `sites` to the packed end, and empty `free_ranges`.
    2. Rewrite every `Family.base`, loose range and
       `Target::Method.feedback_base` held in a site, a block or the
       global cache (`interpreter/inline_cache.rs:66-70`).
    3. Rewrite the heap's holders through `Heap::compact_with(&slide)`:
       each closure's `FEEDBACK_BASE` during the slide, and each header's
       `FEEDBACK_BASE` on the activation stack, in suspension rows and
       in continuation rows. The full collection already visits all of
       them, so this adds no walk of its own.
    4. **Machine code compiled against a moved base is freed.**
       `JitState::free_bodies_with_moved_bases(&slide)` marks free every
       installed body whose `feedback_base` moved, and its slot forgets
       it. That costs a recompile on demand (Risk 2).
       - Rows whose `FeedbackBase` word moved are cleared, since their
         bodies are gone. `Heap::forget_machine_entry` covers each.
       - Every cell is rewritten from its entry
         (`refresh_all_cells`), so no cell names freed code.
       - A frame whose compiled bit is set and whose body was freed
         resumes interpreted (`jit::resumed`), as in Task 18.
       - Machine code is never running here, since `World::collect`
         runs at the safepoint.

    The order matters: step 3 reads the same `SiteSlide` as step 2, and
    step 4 runs after both, so a freed body can never be re-entered at
    a stale base.
