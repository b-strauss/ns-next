# Precompiled shipped code -- design

Decided with the user on 2026-10-14. Temporary: at the end of the batch its
content moves into the living design documents and this file is deleted.

## The problem

Every process start parses, resolves and compiles the six shipped modules
(`Kernel.ns`, `PlatformFactory.ns` and the four under `platform/`), about
9,000 lines, before anything else runs. An image names the shipped world and
does not carry it, so `ns-next load` pays the same cost as `ns-next run`,
whatever the size of the application.

Measured on 2026-10-14 at `f60f6782`, release build, Windows 11, the
measuring workstation, a hello program, 30 runs, median per phase, through
temporary `Instant` marks (not committed):

| Phase | Time | Share of the boot |
|---|---|---|
| Parsing | 5.26 ms | 38% |
| Resolving | 0.98 ms | 7% |
| Compiling (mixins and code) | 6.98 ms | 51% |
| Building classes, instantiating, `complete_shipped_world`, the platform | 0.33 ms | 2% |
| **The boot** | **13.7 ms** | |

| Module | Parse | Resolve | Compile | Rest | Sum |
|---|---|---|---|---|---|
| `Kernel` | 3.44 | 0.67 | 4.53 | 0.17 | 8.8 ms |
| `CollectionsFactory` | 1.05 | 0.17 | 1.57 | 0.01 | 2.8 ms |
| `TypedArraysFactory` | 0.59 | 0.09 | 0.66 | 0.01 | 1.35 ms |
| `PlatformFactory`, `TranscriptFactory`, `TimeFactory` | | | | | 0.5 ms |

The whole process takes 20.0 ms (median of 40), a process that boots nothing
(`ns-next --version`) 2.5 ms.

So 96% of the boot is work whose result is a function of the binary. The
instantiation, the only part that needs a heap, is 2%.

## Decisions

1. **The shipped modules' compiled code is produced ahead of time and
   embedded in the binary**, as an artifact the boot decodes instead of
   parsing, resolving and compiling the source. The world is still built by
   running the binary's own code on the decoded mixins, exactly as today;
   only the mixins come from the artifact.
2. **The artifact is generated by `cargo xtask shipped-code` and is not
   checked in** (`.gitignore`). A tree without it builds and runs, booting
   from source.
3. **Only the optimized lowering is in the artifact.** The reference lowering,
   and `NS_NEXT_NO_PRIMITIVE_METHODS` (read when compiling), always compile
   the shipped modules from source, so the reference lowering stays an
   oracle that compiles everything afresh.
4. **The artifact has a codec of its own**, not a dialect of the image's.
   The image decoder is unchanged and still has no arm for `SendMirror`:
   lock (6) of the VM mirror stays structural ("`SendMirror` has no wire
   tag"). The artifact's decoder is reached only by the boot, with the
   embedded bytes.
5. **One section per module**, each decodable on its own. Loading a module on
   first demand is a second stage, built in this batch only if the
   measurement after the first stage shows it pays (below).

Rejected:

- **Compiling each method on its first call.** It touches only the 51%
  compiling takes, leaves parsing at every start, and puts a "not yet
  compiled" state into the lookup, the image, road step 5's atomic install
  and a later JIT. A large application reaches much of the kernel anyway.
- **An embedded heap snapshot of the shipped world** (Primordial Soup boots
  from one, `prior-art/primordialsoup/vm/main.cc:27`). It would also spare the
  instantiation, 0.33 ms, but holds the mirror and needs a second, trusted
  path through a heap decoder.
- **Generating Rust source that builds the mixins.** Tens of thousands of
  generated lines, and compile times with them.
- **`build.rs` in the binary crates with `ns-runtime` as a build
  dependency**, or **a compiler crate of its own** usable from
  `ns-runtime`'s `build.rs`: the first builds `ns-runtime` twice and leaves
  its own tests without the artifact, the second is a restructuring of the
  interpreter, resolver, mixins and bytecode for a build step.
- **A dialect of the image codec** (one encoding per instruction): lock (6)
  would become a check -- the image decoder would have a `SendMirror` arm
  and refuse it by mode -- and the verification an untrusted image needs
  would have to be switched off for the artifact or paid at every boot.

## Components

### `crates/ns-runtime/src/shipped_code/`

The codec: `encode(&[(name, Rc<Mixin>)]) -> Vec<u8>` and
`decode(&[u8]) -> Vec<(name, Rc<Mixin>)>` (exact signatures in the plan),
and `generate() -> Vec<u8>`, `pub` and `#[doc(hidden)]`, which compiles
every shipped module through the source path (checks included, optimized
lowering) and encodes it. No heap, no interpreter: symbols are interned
afresh when decoding. It may share byte primitives with `image/`, nothing
else. The decoder is `pub(crate)` and called only by the boot.

**The format.** A header -- the magic `NSSC`, a `u16` format version, the
`u64` fingerprint -- then one section per module in `SHIPPED_MODULES`
order, the kernel first: the section's byte length (so a section can be
skipped and later decoded on its own), its symbol table (strings, in order
of first use) and the root mixin, recursively with every nested one. Numbers
are little-endian and fixed-width, as in the image.

**Per mixin:** name, access, slots (name, `mutable`, access, `lazy`), the
factory, the superclass clause and every `<:` clause each with its receiver
name and its code, `has_initializer_expressions`, `initializer_code`,
`superclass_clause_code`, `superclass_message_code`, `root_clause_defect`,
the root shape, `shipped`, the class side, the nested mixins, the `span`,
and the methods, sorted by selector name so the bytes do not depend on a
`HashMap`'s order. A method is `Compiled` (`argument_count`, code,
`fast_path`, `class_accessor`), `SlotAccessor` or `Factory`. `Primitive`
occurs only on the mirror's class, which Rust builds; the encoder panics on
one.

**Not in the artifact:** what only the compiler reads -- `declaration`, the
slots' AST, `initializer_expressions`. A decoded mixin has `None` or an
empty list there; nothing at run time reads them.

**Per `CompiledCode`:** `kind`, `argument_count`, `register_count`,
`copied_count`, `statement_program_counter`, `unwind_marker`, `source` and
the instructions, each complete (`CallSite` and `SendMirror` included),
literals as the image encodes them, `MakeClosure`'s code nested.
`family_size` and `outer_reach` are derived from the instructions as the
compiler derives them, through `from_builder`'s path, so the invariant of
`outer_reach_of` holds by construction.

**No field can be forgotten.** The encoder destructures `Mixin`,
`MixinMethod`, `MixinSlot`, `CompiledCode` and matches `Instruction`
exhaustively, without `..`: a new field or instruction does not compile
until the artifact's treatment of it is decided. A field left out on
purpose says why in a comment.

**No verification.** The bytes are the binary's own. Bytes that do not
decode are a defect of the binary and panic, as a shipped module that does
not parse does today; the decoder has no error type.

### `Mixin` carries what the kernel phase reads from the AST today

The superclass clause's receiver name, each `<:` clause's receiver name and
the root shape (`kernel.rs` reads them at 251, 318 and 606 through
`declaration`). `fill_builtin_classes`, `superclass_kind`, `fill_order` and
`applied_kernel_class` read them from the mixin. The checks against the AST
-- `check_kernel_shape`, `check_mirror_send_arguments`, the `declaration`
asserts -- stay on the source path, so they run when the artifact is
generated and on every fallback. The assert `applied_kernel_class` makes on
`declaration.is_some()` goes; the test at `kernel.rs:983` that checks it
stays, for the source path.

### `build.rs` in `ns-runtime`, with no dependencies

- **The fingerprint of the compiled code**: FNV over the core library's
  `.ns` files and the Rust sources of `ns-syntax` and `ns-runtime`, emitted
  as a constant. It covers everything that can change the compiled code, so
  a local artifact a compiler change made stale is never decoded. It
  invalidates more often than necessary -- any change in those crates --
  and that is safe: the boot falls back until the artifact is regenerated.
- **Embedding**: if `crates/ns-runtime/core-library/shipped-code.bin`
  exists, it is copied into `OUT_DIR`; otherwise an empty file is. The boot
  `include_bytes!`es the copy. `cargo:rerun-if-changed` names the artifact,
  the core library and both crates' `src/`.
- **The image's fingerprint** (`image/fingerprint.rs`) takes a second
  constant from `build.rs`, the hash of the core library's sources alone,
  instead of hashing the sources at run time, plus the builtin classes'
  names and the mirror's selectors as today. An image does not become
  unloadable on every Rust change.

### The boot

A function in `interpreter/core_library.rs` answers each module's root
mixin, in `SHIPPED_MODULES` order, the kernel first:

- **From the artifact** when the lowering is `Optimized`,
  `NS_NEXT_NO_PRIMITIVE_METHODS` is unset, the artifact is not empty and its
  format version and fingerprint match the constants: its section is
  decoded.
- **From source** otherwise: parse, `resolve_kernel`,
  `check_mirror_send_arguments`, compile; `check_kernel_shape` for the
  kernel. This is today's path.

From there both are one path: `fill_builtin_classes` takes the root mixin
instead of the `ResolvedModule`; `load_root_class` is split so that building
the root class from a finished mixin is a function of its own (user
programs unchanged); instantiation, `complete_shipped_world` and the
platform are unchanged.

Unchanged: the boot's order and with it every identity hash (the boot draws
none while it builds); the stress modes (decoding allocates nothing in the
heap); the mirror's six locks (the resolver recorded `Binding::MirrorSend`
when the artifact was generated, the check of the mirror slots after
instantiation runs as today, the image touches none of it).

A stale or missing artifact falls back silently: a slow boot, correct
behaviour. No warning, which would change every golden's `stderr`. A
`#[doc(hidden)]` query says which path the boot took, for the tests.

### `cargo xtask shipped-code`

`xtask` gains `ns-runtime` as a dependency and the task `shipped-code`,
which writes `generate()`'s bytes to
`crates/ns-runtime/core-library/shipped-code.bin`; `--check` writes nothing
and reports whether the file is missing or stale. `cargo xtask gates commit`
runs `shipped-code` first, so the gates always test a current artifact. The
generated bytes are reproducible: symbols in order of first use, methods
sorted by selector name, no `HashMap` iteration.

## Tests

All in the default profile, so in the `commit` gate:

1. **`the_shipped_code_round_trips`**: the embedded bytes, decoded and
   encoded again, are the embedded bytes. With the exhaustive encoder this
   also holds the decoder to every field.
2. **`the_optimized_boot_decodes_the_embedded_code`**: an optimized boot
   takes the artifact, not the fallback. It fails when the artifact is
   missing or stale, saying "run `cargo xtask shipped-code`": a bare
   `cargo nextest run` without the artifact is red with that instruction,
   the gate green. Skipping instead would leave the artifact path silently
   untested.
3. **`the_reference_boot_compiles_from_source`**, its counterpart.
4. **The goldens**, under both lowerings as today: the optimized one now
   boots from the artifact, the reference one from source, so their
   comparison also holds the two paths to the same behaviour. `images`,
   `caches`, `stress` and `benchmarks` are unchanged and run at the end of
   the batch.

## The second stage: loading a module on first demand

After the first stage, measured as above -- release build, the hello
program, 30 runs, medians per phase through temporary `Instant` marks, the
whole process over 40 -- `master` (source) against the branch (artifact):
decoding per module, instantiation, `complete_shipped_world` and the
platform, the boot's sum, the whole process. The numbers, today's included,
go into `execution.md` under "What the precompiled shipped code moved".

**The second stage is built if decoding and instantiating
`CollectionsFactory` and `TypedArraysFactory` together take more than
0.5 ms**; below that the gain is lost in the round-to-round spread of about
0.3 ms on the measuring workstation, and the item goes into `OPEN-WORK.md`
with the numbers. If built: `moduleInstanceNamed:` decodes and instantiates
a module on its first call and keeps the instance; `image::load` builds the
modules the shipped-names section names before the tenure and the graph;
`image-format.md`'s and `memory.md`'s arguments that the loader runs nothing
before the graph and that identity hashes agree are restated. That stage
gets its own design section, with the user, only if the measurement argues
for it.

## Documentation

- `CLAUDE.md`: the module and the artifact in `ns-runtime`'s description;
  after a change to the core library or the compiler, `cargo xtask
  shipped-code` (the commit gate runs it).
- `core-library.md` and `image-format.md`: the boot from the artifact, and
  why lock (6) is untouched; `image-format.md`'s "Shipped names" paragraph
  on the cost of building the world.
- `execution.md`: both measurements.
- `OPEN-WORK.md`: "The cost of building the shipped world at boot" removed
  or restated; the parser's 3.4 ms for `Kernel.ns`, which after this batch
  only `run` from source and the reference lowering pay; a release binary
  without the artifact boots slowly, so a later packaging (`cargo install`
  and the like) needs a way to force it.
- The `measuring-performance` skill: `cargo xtask shipped-code` before
  measuring.
